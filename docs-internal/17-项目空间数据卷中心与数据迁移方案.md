# 项目空间数据卷中心：legacy Contract 清理

项目空间数据卷主链已经切换到 `ProjectVolume + DeploymentVolumeMount + VolumeTransfer`。当前产品
行为以代码、OpenAPI、中英文公开文档和测试为事实源；本文只跟踪仍未完成的旧契约物理清理，
不再重复已实现的接口、页面和任务设计。

## 1. 当前权威模型

- `ProjectVolume` 表达项目空间可管理或引用的数据卷资产及期望配置。
- `DeploymentVolumeMount` 显式关联部署配置与数据卷，区分 Filesystem `volumeMounts` 和 Block
  `volumeDevices`；挂载模式、访问模式和所有权必须明确，不能从旧 JSON 猜测。
- `VolumeTransfer` 记录导入、导出、取消、重试和终态历史；实际数据存于 Kubernetes 卷和
  S3-compatible 对象存储，不进入业务数据库。
- 数据库保存期望配置、资源引用、工作流与不可变历史；PVC、Snapshot、容量、健康和任务当前状态
  从 Kubernetes、CSI 或对象存储权威回读，上游不可达时返回 `unavailable`。

## 2. 长期不变量

- 平台托管卷与外部引用卷的所有权、删除责任和保留语义必须可区分；应用或部署配置删除不能隐式
  删除仍需保留或仍被引用的数据。
- RWO 独占、RWX 共享、Filesystem 与 Block 的限制在保存和最终执行前都要校验；不能用强制参数
  绕过活动引用、拓扑、容量、配额或权限冲突。
- 导入导出是可取消、可重试、幂等的异步流程。成功必须经过对象/卷权威回读，失败和取消必须有
  稳定终态，分块租约不能用长数据库事务包住外部存储写入。
- Secret、对象存储凭据、归档内容和用户路径不得进入遥测；跨 HTTP、Asynq、Kubernetes Job、CSI
  与对象存储调用保持 Trace Context，并使用低基数状态。
- 存储计费只面向受计费规则覆盖的托管资产和不可变计量窗口；实时容量与历史账单不得互相冒充。

## 3. 剩余 Contract 清理

在删除旧表和字段前完成以下门禁：

1. 对目标环境执行备份与恢复演练，运行可重入对账，确认旧保留卷和部署目标旧存储字段已经完整
   映射到新模型，且不存在孤儿引用、重复归属或未结束任务。
2. 验证 API、Worker、Agent、Web、CLI 契约、异步载荷、公开文档和测试不再读写旧模型；fresh DB
   的运行路径不能依赖 legacy backfill、旧导出路由或兼容 fallback。
3. 删除运行时 legacy 模型、迁移服务、一次性迁移命令、旧字段和只服务旧路径的测试/文档；历史 SQL
   迁移是否保留由数据库升级策略决定，不能为目录整洁改写已发布迁移历史。
4. 通过可销毁 PostgreSQL、Kubernetes、对象存储和 OTel 环境，覆盖 fresh install、历史升级、
   对账、取消、权限拒绝、计费终态、Asynq 跨服务 Trace 以及不可逆迁移失败时的 fail closed。
5. 完成后从 `TODO.md` 删除未完成项并删除本文；后续数据卷行为继续由代码、OpenAPI、公开文档和
   场景测试维护。

## 4. 明确不做

- 不恢复旧 `retained_volumes` 或部署目标 JSON 作为运行时兼容分支。
- 不把当前 Kubernetes 状态写回业务表或用缓存延续旧状态。
- 不为未知未来需求预建第二套迁移框架、固定 Top K Agent 工具门禁或人工维护的工具白名单。
- 不在未完成备份、对账和外部链路验收前执行不可逆 Contract DROP。
