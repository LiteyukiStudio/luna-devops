# Luna DevOps 可观测插桩与验收标准

本文定义 API、Worker、Agent 和 Web 的统一 OpenTelemetry 约束。接入事故和一次性验收结果由
版本历史保存，不在本规范累积。

## 1. 覆盖目标

必须覆盖：

- 每个 HTTP、SSE、WebSocket 和内部服务请求。
- 每次 PostgreSQL、Redis、Asynq 和外部 Provider 调用。
- 异步任务的投递、排队、领取、重试、执行和终态。
- Agent Run、模型轮次、工具调用、审批、交互卡片和持久化。
- 构建、发布、部署、回滚、网关、证书、计费和通知等业务阶段。

每个边界至少具备 Span；关键状态转换同时具备结构化日志；可聚合结果同时具备 Metric。禁止只
给入口创建 Span 而把数据库、外部调用和内部阶段留作黑盒。

## 2. 运行配置

```env
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_RESOURCE_ATTRIBUTES=deployment.environment.name=production
OTEL_EXPORTER_OTLP_HEADERS=api-key=replace-me
```

仅 endpoint 非空时启用导出；为空时使用无操作 Provider，不要求部署 Collector。统一使用 OTLP
HTTP/protobuf。服务名由进程固定：

- `luna-devops-api`
- `luna-worker`
- `luna-agent`
- `luna-web`

## 3. Trace

### 3.1 命名与层级

- Span 名必须使用稳定模板，不得包含用户、项目、资源、请求、查询参数等高基数值。
- HTTP Server Span 使用路由模板；数据库 Span 使用系统、操作和表语义，不记录 SQL 参数。
- 外部 Client Span 使用稳定操作名，例如 `registry.manifest.get`。
- 业务阶段使用稳定名称，例如 `release.prepare`、`build.enqueue`；GenAI Span 使用本节 Agent 规则指定的官方模板。
- 资源 ID 只可作为 Span attribute 或受控日志字段，不可作为 Span name 或 Metric label。

### 3.2 Context 传播

- HTTP 使用 W3C `traceparent`、`tracestate`；Baggage 仅在确有需要时使用。
- EventSource/WebSocket 的私有桥接参数进入 API 后必须立即转入 Header 并从 URL 删除。
- Asynq 只传播遥测 Context，不复制 Cookie、Token、正文或用户输入。
- Worker Consumer 继承 Producer；长时间批处理可使用 Span Link。
- API、Agent、SSE/WebSocket 与数据库排队的 Agent Run 必须延续父链。
- 持久化的遥测 Context 只包含白名单、限长后的 `traceparent` / `tracestate`，不得参与业务幂等
  哈希、进入 Timeline 或响应。
- Request ID 用于用户报错和日志检索，不替代 Trace ID。
- 业务链路不得使用 `context.Background()` 截断现有父 Context。

### 3.3 结果与异常

- 业务拒绝、依赖失败和失败终态设置 Error，并记录稳定 `error.code`。
- 同一错误只在拥有终态语义的边界输出一次 Error 日志；下层只包装并记录 Span 异常。
- Secret、Token、Cookie、正文、Prompt、工具敏感参数和第三方凭据不得进入遥测。
- 只有 `AI_OBSERVABILITY_CAPTURE_CONTENT=true` 时可通过统一入口记录经强制脱敏和限长的模型
  与工具内容；凭据在任何模式下都禁止记录。

## 4. 结构化日志

Go 使用 `slog` JSON，Agent 使用 Pino JSON；通过 OTel 桥接导出并保留 stdout。

关键日志至少包含：

| 字段 | 约束 |
| --- | --- |
| `event.name` | 稳定事件名 |
| `service.name` | 固定服务名 |
| `trace_id` / `span_id` | 当前链路关联字段 |
| `request_id` | 存在时记录用户可见请求编号 |
| `operation` | 稳定业务操作 |
| `outcome` | `succeeded`、`failed`、`cancelled`、`rejected` |
| `error.code` / `error.type` | 失败时的稳定分类 |
| `resource.type` / `resource.id` | 仅日志和 Span 使用，不进入 Metric label |

级别：

- `INFO`：启动、操作开始/完成、状态转换、任务与审批终态。
- `WARN`：重试、可恢复依赖故障、降级、拒绝和限流。
- `ERROR`：失败终态、不可恢复依赖错误和启动失败。
- `DEBUG`：开发细节，不得替代缺失的关键 INFO 日志。

## 5. Metric

Metric 只使用有限枚举和低基数标签。用户、项目、应用、请求、Trace、URL、错误正文和资源名
禁止成为标签。

至少提供：

- RED：次数、错误、耗时和进行中数量。
- 依赖：PostgreSQL/Redis 连接池和外部平台调用结果。
- Worker：队列深度、等待/执行时间、重试、丢弃和终态。
- Agent：Run、模型、Token、工具、审批、中断和耗时。
- 交付：构建、发布、部署、回滚、网关和证书结果。
- 平台：通知/Webhook、计费、观察不可用、认证拒绝和限流。

通用指标：

```text
luna_devops_operation_total{service,domain,operation,outcome}
luna_devops_operation_duration_seconds{service,domain,operation}
```

Prometheus `/metrics` 可作为兼容入口，但新业务指标必须由统一 OTel Meter 生成。

## 6. 模块规则

### API

- 所有 Gin 路由经过 Trace 中间件，并以路由模板命名。
- GORM、`database/sql`、Redis、HTTP 和 Kubernetes Client 在构造处统一插桩。
- Handler 只补业务阶段；Repository/Provider 负责依赖边界。
- SSE/WebSocket 记录建连、断开和终态，不为心跳建 Span。

### Worker

- Producer 注入 Context，Consumer 提取并建立消费 Span。
- 每次尝试独立记录执行 Span，重试与原业务链路关联。
- Provider Client 负责外部调用插桩，业务阶段另建 Span。

### Agent

- 一个 Run 是业务边界；模型、工具和持久化是子 Span。
- GenAI 语义固定对齐 OpenTelemetry `gen-ai-dev/1.42.0-dev`（上游提交 `a685613a207a580163353b8e48a7ad88967e7b42`），Tracer 必须声明 Schema URL `https://opentelemetry.io/schemas/gen-ai-dev/1.42.0-dev`。上游约定仍为 Development；升级版本必须同步 Agent、Tempo 归一化、Web 消费、Grafana 查询、契约测试和本文档。
- Agent 调用 Span 使用 `invoke_agent {gen_ai.agent.name}`、INTERNAL Kind 与 `gen_ai.operation.name=invoke_agent`；模型调用使用 `{operation} {gen_ai.request.model}`、CLIENT Kind 与对应 `gen_ai.operation.name`；工具调用使用 `execute_tool {gen_ai.tool.name}`、INTERNAL Kind 与 `gen_ai.operation.name=execute_tool`。
- 官方 `gen_ai.*` 只承载规范字段；Luna 的运行、轮次、内容限长和业务阶段等扩展继续使用 `luna.*`，不得在 `gen_ai.*` 下伪造项目自定义字段。
- 开启高敏内容采集后，`gen_ai.system_instructions`、`gen_ai.input.messages`、`gen_ai.output.messages`、`gen_ai.tool.definitions`、`gen_ai.tool.call.arguments` 和 `gen_ai.tool.call.result` 必须遵循对应官方 JSON Schema。Span API 不支持嵌套 AnyValue 时允许使用有效 JSON 字符串；超过限长必须整项省略并写入 `luna.ai.content.truncated=true`，禁止截断 JSON 文本。
- 有上游 Context 时继承；没有时才创建根业务边界。
- Node 只引入真实使用的单项 instrumentation，禁止为方便引入包含无关依赖的全量元包。
- Fastify、HTTP、数据库、日志和出站请求各自只有一个责任明确的 instrumentation。
- Fastify handler Span 统一使用 `fastify.<hook> <METHOD> <route template>` 稳定模板，禁止将回调函数源码、函数名或实际 URL 拼入 Span 名。
- 流式响应只记录首 Token 与终态，不为每个 Token 建 Span。
- 高敏内容只能经统一 `recordAIContent` 入口写入受控 Span 属性和关联日志。
- 工具目录刷新使用稳定的成功/失败结果、来源和版本计数建立 Span、结构化日志与低基数 Counter；
  目录正文、operationId 集合和用户检索词不得进入普通遥测属性、日志字段或 Metric label。工具检索
  只记录是否存在 query、分页参数、候选数、自动加载数、缓存命中和 Catalog digest 等稳定元数据。

### Web

- 页面导航、用户操作和 API 请求建立浏览器 Span，并向 API 注入 W3C Context。
- 只上报路由模板、操作类型、耗时和稳定错误码，不上报表单、DOM、查询值和本地存储。
- 浏览器遥测失败不得阻塞主流程。

## 7. 自动化门禁

1. 所有 Gin、Asynq、Agent Tool 和 Provider 使用统一包装器。
2. 所有数据库、Redis、HTTP、Kubernetes Client 使用统一构造器。
3. 禁止新增 `log.Printf`、裸 Client、未插桩连接和输出敏感字段的日志。
4. 新增 Node instrumentation 前审计生产依赖树。
5. 测试至少断言父子传播、错误状态、日志关联字段、稳定标签和敏感字段缺失。
6. AI 内容默认不出现；高敏模式仅出现已脱敏和截断内容，任何模式都不得出现凭据。

## 8. 端到端验收

使用 `docker-compose-dev-observability.yaml` 或等价临时外部栈，至少验证：

1. 一个带数据库访问的 API 请求。
2. 一个 Redis/Asynq 任务从投递到消费终态。
3. 一个失败的外部依赖调用。
4. 一个包含模型、工具和持久化的 Agent Run。
5. 一个 Web 到 API 的跨服务请求。

通过条件：

- Trace 可看到入口、内部依赖和业务阶段的正确父子关系。
- 失败 Trace、日志和 Metric 时间窗口可关联，错误码稳定。
- Collector 不可达时业务继续运行，stdout 可用，导出器不会阻塞退出。
- 默认模式下抽查不到 Token、Secret、Cookie、密码、Prompt、正文和高基数标签；高敏内容模式
  只出现经统一入口脱敏和限长的正文，仍不得出现凭据。
- 单次验收数据卷、日志和导出物不进入仓库。

## 9. 查询与仪表盘约束

- “Grafana 无数据”按应用插桩、Collector、存储/抓取、Grafana 查询四层逐级验证。
- Prometheus 必须抓取业务指标出口，不能把 Collector 自身指标误当业务指标。
- Trace、Logs、Metrics 分别用 Tempo、Loki 和 Prometheus 原生入口验证后再组合仪表盘。
- Loki 字段可能是结构化元数据；先在 Explore 确认字段，再决定是否使用 JSON 解析阶段。
- ID 自由输入变量使用 `:raw`；多选枚举变量按需使用 `:regex`，并用 Query Inspector 检查最终查询。
- Tempo 查询优先正向选择稳定业务根 Span；不要用负向过滤隐藏数据库子 Span。
- Dashboard JSON 修改后提升版本、覆盖导入，并用真实新数据同时核对仓库 JSON 与线上界面。
- 大内容查询缩短时间窗口并按 Conversation/Run/Trace ID 收窄；高敏内容面板不得在总览自动加载。
- 高敏内容观测只在明确排障窗口开启，设置短保留期和受控权限，完成后关闭并重启 Agent。
