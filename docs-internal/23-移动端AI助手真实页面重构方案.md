# 移动端 AI 助手真实页面重构方案

## 1. 目标

移动端 AI 助手改为真实 `/ai-assistant` 路由页面，删除全屏 Portal 和手写半屏会话层。桌面端继续
保留浮窗，但页面与浮窗只负责展示，共享唯一 Runtime、会话状态、
草稿、Mutation、Pending Action 与 SSE Stream Manager。

## 2. 不变量

- 任意时刻最多渲染一个 AI Assistant Surface；路由页面优先于桌面浮窗。
- 每个 Run 最多一条 Web SSE 连接；切换页面、浮窗或横竖屏不得重建 Runtime。
- Timeline、Composer、ConversationList、ToolCall 与交互卡片只保留一套业务组件。
- 进入助手页时保存最近非助手业务页面；Agent `pageContext` 继续使用该来源，而不是
  `/ai-assistant`。
- 移动页进入时不自动聚焦输入框；普通 Enter 换行，显式发送或 `Cmd/Ctrl + Enter` 才提交。
- 移动会话列表使用完整页面视图，不在聊天页上叠加半屏面板。
- 移动页始终位于当前路由 DOM 内，不使用 Portal；默认由 `dvh` 承载，仅在 WebKit 软键盘
  不缩减布局视口时，用页面内联的 `visualViewport` 尺寸适配保证 Composer 可见。
- Header、Timeline、ConversationList 与 Composer 在各自边界只处理一次对应 safe-area。

## 3. 结构

```text
Authenticated AppLayout
└─ AIAssistantRuntimeProvider
   ├─ immersive /ai-assistant route
   │  └─ AIAssistantPage -> shared ChatSurface / ConversationList
   └─ non-assistant routes
      └─ AIAssistantDesktopHost -> shared ChatSurface
```

桌面浮窗仅在宽度至少 1024、可用高度至少 600、细指针且支持 hover 时启用；其他设备入口均
导航到真实页面。已进入助手路由后不因视口增大自动切回浮窗。

## 4. 路由与上下文

- `/ai-assistant` 是已登录路由；聊天与完整会话列表通过安全的历史 state 切换。
- 从业务页进入时保存内部 `pathname/search/hash`，拒绝协议 URL、协议相对 URL 和助手路由自循环。
- 页面返回优先恢复合法来源；直接访问时回退 `/dashboard`。
- Runtime 分离浏览器实际位置与最近业务位置：前者用于导航成功确认，后者用于
  `buildAIPageContext`、建议操作、Tab、筛选和新会话项目归属。
- 浮窗因响应式断点切换为页面时只切换 Surface，不失效当前 Run 的 Action Session；只有用户
  真正关闭浮窗、离开助手页或能力被禁用时才失效。
- 用户关闭浮窗或离开助手页后，已失效的 Pending Action 请求不得再触发自动导航。

## 5. 调用链边界

- Web：修改路由、布局、状态所有权、页面上下文来源与移动交互。
- API：不适用；请求、响应和 SSE Schema 不变。
- Worker：不适用。
- Agent：不修改；仍消费现有 `pageContext` Schema，仅由 Web 提供正确的业务来源值。

## 6. 验收

- 单元与集成测试断言 Runtime/Stream Manager 唯一、来源路由校验、返回历史和移动键盘语义。
- 移动视口覆盖 320×568、390×844、414×896、844×390 和 768×1024；桌面冻结 1280×800。
- 真机或等价浏览器验收打开、会话列表、键盘开合、横竖屏 safe-area、流式输出、
  Agent 导航、在途 Pending Action 与返回竞态。
- 完成 Web test、singletons、i18n、lint、build 与文档站 build 后再删除旧移动实现并关闭 TODO。
