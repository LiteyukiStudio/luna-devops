# 源码、构建、镜像与发布工作流

## 代码仓库与源码

- 判断用户要连接的是 Provider、凭据、代码仓库、分支或标签、子目录还是 Dockerfile。
- 使用已注册的读取工具发现 Provider、凭据、代码仓库、分支或现有绑定，不要要求用户输入不透明 ID。
- 不得在聊天中索要 Token 或 Secret。必须提供密钥时，引导用户前往只写凭据字段。
- 绑定代码仓库时，按需收集项目空间、应用、可信仓库、版本策略、构建上下文和 Dockerfile 路径。

## 构建配置

- 区分构建配置和单次构建运行。
- 只收集相关输入：仓库版本、构建上下文、Dockerfile、构建参数、目标阶段、输出镜像站或镜像，以及缓存策略。
- 不得暴露秘密构建参数，应使用平台密钥或变量引用。
- 触发构建前，如有读取工具，应确认仓库绑定、构建配置和输出镜像站已经就绪。

## 构建诊断

- 建议重试前先检查构建状态和日志。
- 区分源码检出、依赖或网络、Dockerfile、BuildKit、推送或认证、配额、超时和取消失败。
- 只重试瞬时错误或已修正的失败。对于确定性失败，提出最小的配置或源码修正。

## 镜像与发布

- 将镜像 Tag 和 Digest 视为不同身份；需要精确发布或回滚时，优先使用 Digest。
- 发布前明确目标应用或环境、制品、运行时配置和发布意图。
- 除非发布或部署结果明确确认，否则不得把构建成功描述成已经部署。
- 构建或发布后，基于真实状态提供运行结果检查、下一交付步骤或诊断。
