# 用户场景测试规范

本文定义 Luna DevOps 的端到端用户场景覆盖。已完成操作、环境资源 ID、问题流水和复测结论进入
`TODO.md`、Issue、PR 或测试报告，不在本规范长期累积。

## 1. 验证原则

- 从真实 UI、CLI 或正式 API 入口进入，验证到最终副作用和权威回读，不只检查单个接口。
- 先跑成功主路径，再覆盖失败、取消、权限、并发、重试和恢复。
- API、Worker、外部 Provider 与 Agent 中实际参与的层必须在同一场景中保持契约一致。
- 实时状态从 Kubernetes 或外部平台回读；不得用数据库旧值或前端缓存冒充成功。
- Secret 只验证可写入、不可回显、可替换和遥测不泄露，不在记录中保存真实值。
- 发现缺陷时先记录稳定复现条件；未完成事项进入 `TODO.md`，修复后用原场景复测。
- 平台尚未发版时不为旧数据和旧路由保留无产品价值的兼容路径。
- 不把连接开发数据库、接受宽泛状态码或缺少 Worker 终态的脚本当作端到端验收。自动化 E2E 只有在
  PostgreSQL、Redis、Worker、Agent 和 Kubernetes 均使用隔离可销毁环境并具备可靠清理后才建立入口。

## 2. 通用前提

- 平台管理员已完成初始化，API、Worker、PostgreSQL 和 Redis 正常。
- 至少存在一个可用 Kubernetes/K3s 集群和一个可用镜像站。
- 代码构建场景还需要可用 Git Provider、仓库凭据和 BuildKit 构建能力。
- 准备 Owner/Admin、Developer、Viewer 和平台管理员账号，使用最小权限执行各自路径。
- 验收使用隔离且可销毁的项目空间、命名空间和数据库；清理动作不得影响其他环境。
- 需要验证 Trace/Logs/Metrics 时启用本地可观测栈或等价外部栈。

## 3. 核心场景

### 3.1 平台初始化与资源连接

覆盖：管理员初始化、站点设置、OIDC/Git Provider、镜像站、运行集群和系统状态。

通过条件：

- 普通用户不能维护平台级敏感连接。
- 凭据保存后不回显，连接测试返回稳定状态和安全错误码。
- 集群、镜像站和 Provider 的当前状态来自权威上游；不可达时显示 `unavailable`。

### 3.2 从代码仓库交付多服务项目

覆盖：项目空间、成员、应用、仓库绑定、多个部署配置、Dockerfile/上下文、构建、镜像推送、
Release、自动发布、日志、访问入口和回滚。

建议使用包含 API、Web 和 Worker 的 monorepo，分别配置开发与生产部署配置。

通过条件：

- 每个可独立部署服务对应独立应用，构建与 Release 不会跨部署配置串线。
- Webhook 只触发匹配分支/标签的部署配置。
- 构建结果包含可追溯镜像 digest、提交和日志；发布后回读真实工作负载状态。
- 回滚只能选择同一应用和部署配置的历史 Release，并形成审计记录。

### 3.3 从已有镜像直接部署

覆盖：无需 Git Provider 的应用创建、镜像来源部署配置、端口、资源规格、Release、Service、
运行日志和访问入口。

通过条件：

- 用户可以只用可信镜像完成部署，不被迫配置代码仓库。
- 镜像架构、拉取权限或启动失败时展示稳定原因和可执行排障入口。
- 页面成功状态与 Kubernetes 工作负载、Service 和入口的权威状态一致。

### 3.4 运行配置、Secret 与持久数据

覆盖：普通环境变量、配置集、配置文件、Secret、PVC、重启、重新部署、数据导出和 Web Console。

通过条件：

- Secret 不回显，不进入日志、Trace、命令历史和导出元数据。
- 配置变更明确区分保存、重启与创建新 Release；旧值不会错误写入已切换资源。
- PVC 与 `emptyDir` 的保留语义、风险和权限清晰；危险操作需要参数绑定确认和审计。
- Web Console 绑定当前资源和权限，连接关闭后旧回调不得写入新资源。

### 3.5 项目协作与权限

覆盖：成员邀请/移除、Owner/Admin/Developer/Viewer、平台管理员、费用归属转移和资源删除。

通过条件：

- 后端是权限最终判断者，伪造项目 ID、跨项目引用和越权写入均失败。
- 最后 Owner、关键资源引用、计费归属和危险删除保持业务不变式。
- 权限变化立即影响 API、SSE/WebSocket、Agent Tool 和 CLI，不依赖重新登录绕过。

### 3.6 自动化、Access Token 与 CLI

覆盖：Access Token/OAuth 登录、Scope、默认项目空间、JSON 输出、非交互构建/发布、实时会话校验和撤销。

通过条件：

- Token 只具有声明 Scope，撤销与过期后不可继续使用。
- 高风险命令不会因非交互或 Agent 模式绕过确认、实时会话、RBAC 和审计。
- 自动化只解析稳定 JSON，不依赖本地化文本；CLI 与平台 OpenAPI 契约一致。

### 3.7 服务依赖与拓扑

覆盖：同项目服务引用、环境变量注入、手工拓扑、诊断、删除保护和重新发布。

通过条件：

- 手工关系只用于展示，不修改运行时。
- 服务引用在发布时解析稳定 Service 地址，不保存 Pod IP 或 Secret。
- 目标不可用时诊断来自实时 Service/Endpoint/NetworkPolicy；活动引用阻止误删目标。

### 3.8 失败诊断与恢复

至少制造镜像拉取失败、容器启动失败、外部 Provider 不可达、构建网络拒绝、入口不可达和异步
任务取消各一条路径。

通过条件：

- UI 说明失败阶段、稳定错误码和下一步，不直接展示后端堆栈。
- Trace 标记首个失败边界，日志可通过 request/trace/task/run ID 关联，Metric 使用低基数标签。
- 修复后沿原路径重新执行，并从权威上游确认恢复；旧失败状态不冒充当前事实。

### 3.9 AI 助手业务闭环

覆盖：只读查询、结构化补充输入、普通写入、高风险逐次审批、工具失败、取消和恢复。

通过条件：

- Agent Tool 使用当前用户委托、Scope 和平台 Handler，不复制业务权限或执行逻辑。
- 交互卡片只收集/展示受控数据，最终副作用由平台注册操作执行。
- 完成状态必须经过执行、权威回读和明确终态结论；模型不得猜测任务进度。
- Prompt、工具敏感参数和 Secret 不进入遥测；Trace 延续到模型、工具和平台 API。

专项矩阵还必须覆盖：

- OpenAPI 普通操作自动进入目录、特殊协议按稳定原因排除，空查询可分页遍历完整目录。
- 用 operationId、中文和英文业务词检索到正确摘要；摘要不携带 Schema，非空 `search_tools`
  自动加入少量高相关候选，`get_tool_details` 只用于精确选择和消歧。已选择工具在整个 Run、审批和
  输入恢复后持续可见，完整目录仍可空查询分页遍历，不设置固定 Top K 门禁。
- 普通读取、可回收写入和最终权威回读；不存在的能力必须先检索，再明确阻塞，不能虚构成功。
- `reject`、`approve`、`approve_always` 与撤销；决策绑定当前 toolCallId、operationId
  和用户可见的脱敏参数摘要，豁免仅按当前用户与 operationId 生效。
- 不同用户、登录 Session、会话和项目空间交叉调用均 fail closed，Owner/Admin/Developer/Viewer
  使用真实 RBAC 结论。
- SSE 序号缺口恢复、服务中断的 `interrupted` 终态、取消和上下文压缩失败的安全回退。
- `present_card`、`request_input`、`request_choice` 的结构化交互；Secret 只通过专用直达动作提交，
  不进入聊天、模型上下文、事件和遥测。
- AI 用量只归属发起用户，计费记录 `project_id` 为空；模型、工具和平台 API 的 Trace 父子关系完整。

## 4. 验收记录格式

每轮验收记录只保留对当前事项有用的证据，事项关闭后依赖 Issue/PR/提交历史归档，不回填本文。

```md
## YYYY-MM-DD 场景名称

- 基线提交与环境：
- 入口和测试账号角色：
- 覆盖层：Web / API / Worker / Provider / Agent
- 前置资源：使用匿名标识，不记录 Secret
- 成功路径与权威回读：
- 失败、取消或权限路径：
- Trace / 日志 / Metric 证据：
- 发现：稳定编号 / 复现条件 / 影响 / 分级
- 修复与原路径复测：
- 未覆盖范围和已接受限制：
```

状态只使用：`待修复`、`修复中`、`待复测`、`已复测`、`已接受`。不能把“代码已修改”标记为
“已复测”，也不能仅以任务已提交作为业务成功。

## 5. 清理与安全

- 场景完成后清理隔离项目、临时域名、命名空间、测试凭据和本地数据卷。
- 删除前核对资源标签和归属；共享集群、数据库和真实用户数据不得进入自动清理范围。
- 临时日志、截图和导出物不得提交；确需保留的脱敏证据放入对应 Issue/PR 或受控制品存储。
