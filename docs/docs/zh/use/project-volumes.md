# 管理项目空间数据卷

项目数据卷是独立于应用的持久数据资产。创建后可以在同一项目空间、同一运行集群的部署配置中挂载；删除应用或解绑部署配置不会自动删除数据卷。

## 前置条件

- 项目 Viewer 可以查看数据卷；Developer 可以创建、引用、纳管和扩容。纳管已有 PVC 需要明确确认其生命周期将交给平台。
- 导出需要项目 Owner/Admin 的 `volume:export` 权限；永久删除或移除外部引用需要 `volume:delete` 权限。
- 目标运行集群必须可用。创建空白卷前还需要选择集群提供的 StorageClass。

## 创建数据卷

1. 打开项目空间，进入“数据卷”。
2. 选择“创建数据卷”，填写名称、运行集群、容量、StorageClass、访问模式和卷模式。
3. 选择来源：
   - **空白卷**：创建新的平台托管 PVC。
   - **已有 PVC**：引用或纳管项目 Namespace 中的 PVC。引用不会删除或计费底层 PVC；纳管会把生命周期交给平台，需要再次确认。
   - **VolumeSnapshot**：从同集群可用快照恢复。
4. 提交后等待状态变为“就绪”。`WaitForFirstConsumer` StorageClass 可能在首次挂载前保持 Pending，这不代表创建失败。

AI 助手可以列出当前项目空间的数据卷和目标集群 StorageClass，并在确认参数后创建空白卷、引用已有 PVC 或从 VolumeSnapshot 恢复。纳管已有 PVC 等高风险操作需要对当前参数逐次批准；助手不会用占位 ID 或 `emptyDir` 代替持久卷。

集群暂时不可达时，页面会显示“观察不可用”，不会沿用旧的 PVC 状态。修复连接后刷新或重试最近操作。

## 容量配额与余额

托管卷在创建、纳管、快照恢复或导入开始时预留全部容量，扩容时只预留增加量。外部引用卷不占用托管容量配额，也不按平台托管存储计费。发起托管卷创建、导入、扩容或相关重试前，项目空间计费归属账户必须有正余额。

平台管理员可以在“全局设置 → 计费配置”中设置每个项目空间的托管卷容量上限。默认值 `0` 表示不限制。降低上限不会截断或删除现有卷；如果现有用量已经超过新上限，新的创建、扩容和相关重试会被拒绝，直到管理员提高上限或项目删除不再需要的托管卷。

初次创建或导入失败、取消时会释放本次预留；扩容失败时只释放扩容量。托管卷完成永久删除后，其容量才从项目空间配额中释放。

## 挂载到部署配置

1. 编辑应用的部署配置，在“数据卷”中添加挂载。持久化数据只能选择卷中心已就绪的项目数据卷；临时数据可选择 `emptyDir`。
2. 选择“项目数据卷”，按名称搜索同集群可用卷。
3. Filesystem 卷填写绝对 `mountPath`；Block 卷填写绝对 `devicePath`。只有卷访问模式允许时才能选择只读或共享挂载。
4. 保存并创建新 Release。

卷会先显示“已预留”。只有 Worker 从 Kubernetes 工作负载权威回读到对应 PVC 后，才显示“使用中”。切换或移除卷后同样需要一次成功发布；确认旧工作负载不再引用后，卷才恢复“可用”。

从应用市场安装声明了持久数据卷的模板时，安装表单会要求选择同项目空间、同集群且卷模式匹配的已就绪项目数据卷。未选择真实数据卷时安装会被拒绝，不会自动创建 PVC，也不会降级为 `emptyDir`。

## 扩容或删除

- 容量只能增加。StorageClass、访问模式或卷模式不能就地修改；需要创建新卷并迁移数据。
- 删除前先查看删除影响。存在预留/活动挂载或运行中传输时，平台会拒绝删除。
- 托管卷的“永久删除”会删除底层 PVC，无法恢复；外部引用只能“移除引用”，不会删除 PVC。两种操作都需要 Owner/Admin 权限和明确确认。

需要迁移或备份数据时，参见[导入与导出数据卷](./volume-transfer.md)。
