# 使用内嵌 AI 助手

Luna DevOps AI 助手用于解释构建、发布、Pod、Gateway、证书与通知问题，并把分散在多个页面的状态整理为一条可恢复的诊断时间线。它代表当前登录用户工作，不拥有额外权限，也不会绕过项目角色、OAuth Scope 或 Step-up MFA。

## 打开助手

只有部署开关、站点开关、Agent 健康、模型配置、成本限制与当前用户权限同时满足时，登录后的控制台才会显示助手入口。能力未知、Agent 不可用或任一配置缺失时，入口不会出现。

桌面端使用可拖动和调整尺寸的悬浮窗口；移动端使用全屏界面。关闭窗口、刷新页面或网络断开只会停止当前浏览器订阅，不会取消已经持久化的运行。

## 阅读时间线

时间线把内容分成三类：

- **Thinking**：只展示模型允许公开的思考摘要，或明确标记为“执行进度”的平台状态。原始隐藏推理不会展示。
- **Message**：用户输入和助手最终回答。
- **Tool Call**：助手调用平台能力的记录。默认折叠，展开后显示经过脱敏的参数、结果、状态和耗时。

正在更新的 Thinking 使用三行视窗并跟随最新摘要。用户向上滚动后会暂停自动跟随，可以随时回到最新位置。

## 页面联动

部分 Tool Call 会提供“打开发布事件”“查看 Pod”或“切换到部署 Tab”等操作。这些操作通过前端注册的声明式 UI Action 执行，只能使用平台路由、Tab、筛选器与对话框白名单，不能执行任意脚本、DOM Selector 或外部 URL。

表单预填只会填写允许的非密钥字段，不会自动保存。保存仍通过普通业务 API、权限检查和审计。

## 批准与 MFA

写操作或高风险操作会暂停运行并展示：

- 具体工具和操作类型；
- 目标项目空间、应用、环境或资源；
- 已绑定的完整参数；
- 预计影响与风险等级。

批准只对当前参数哈希有效。参数变化后必须重新批准。需要 Step-up MFA 时，批准不能代替 MFA；验证完成后运行才会重新排队并从检查点继续。

## 会话与恢复

会话保存在 Agent 持有的 `ai` schema 中，不写入浏览器 LocalStorage。重新打开会话时，前端先读取完整 Timeline，再从持久事件游标继续订阅。重复事件会按事件、Item、Part 和 Tool Call ID 去重。

删除会话成功后会物理级联删除消息、运行、事件、工具调用、批准和检查点，不提供软删除或恢复宽限期。

## 安全边界

- 浏览器只连接 Luna API，不直接连接模型或 `luna-agent`。
- Agent 只能调用 OpenAPI 白名单中的平台 operation。
- 每次工具调用都由 Luna API 重新计算权限。
- Secret、Token、Cookie、Authorization Header 和 kubeconfig 不进入普通会话、SSE 或模型上下文。
- 工具结果和模型输出在发送到浏览器前都会经过统一脱敏。
