# 导入与导出部署配置

部署配置可以导出为 JSON，再导入当前平台中的另一个应用。导入只会新建配置，不会覆盖现有配置，也不会自动开始构建或发布。

## 导出配置

1. 打开应用的“部署”页。
2. 在目标部署配置的操作菜单中选择“导出 JSON”。
3. 妥善保存下载的文件。

文件包含运行规格、构建设置、发布策略和非敏感配置，但不包含账号凭据、Secret 值、源项目空间的资源 ID、运行状态或构建与发布历史。即使不含 Secret，文件仍可能包含镜像地址、环境变量和配置文件内容，请按内部配置资料管理。

## 导入配置

1. 打开目标应用的“部署”页，选择“导入 JSON”。
2. 选择导出的 JSON 文件。
3. 确认目标名称、阶段和命名空间。
4. 处理预检列出的资源映射，并重新填写 Secret。候选资源较多时，可按名称或类型搜索、排序并翻页选择，不需要手填资源 ID。
5. 状态变为“可以导入”后，选择“导入配置”。

导入成功后，配置会出现在列表中。平台不会自动构建或发布，请检查配置后再手动执行后续操作。

## 处理不受支持的阶段

公开部署阶段只允许 `dev`、`test`、`staging` 和 `prod`；文件中的 `production` 会按 `prod` 处理。如果旧文件或已有配置导出的文件包含 `qa` 等其他阶段，首次预检会显示阶段无效，且不会创建部署配置、Secret、构建环境或数据卷挂载。

请在目标阶段选择器中选择一个允许的阶段，再选择“重新预检”。预检变为“可以导入”后才能提交。不要直接编辑摘要值或复用无效预检的摘要；导入提交会再次检查文件、覆盖值和预检摘要。

## 跨项目空间或导入空应用

导入文件只描述依赖，不会复制依赖资源：

- 源码来源必须选择目标应用已经绑定的代码仓库。目标应用没有仓库时，请先完成仓库绑定，再重新预检。
- 源码构建必须选择当前项目空间可用、并配置了推送凭据的镜像站。
- 集群、构建变量集、运行配置集、Hook 和项目数据卷必须映射到目标项目空间中可访问的现有资源。
- 项目数据卷只建立挂载关系，不复制 PVC 或数据。需要迁移数据时，请先使用[数据卷导入与导出](./volume-transfer)。
- 镜像来源只要镜像地址和其他依赖有效，就可以导入没有仓库和构建历史的空应用。

没有候选、存在多个候选、无权访问或资源不兼容时，平台不会创建部分配置。请先补齐或调整目标资源，再重新预检。

## 常见问题

### 为什么必须选择新阶段？

同一应用中的阶段必须唯一。第一版导入不会覆盖或合并已有部署配置，请选择未使用的阶段。

### 为什么要重新填写 Secret？

导出文件只记录 Secret 的用途和键名，不导出原值或存储引用。新值会在确认导入时加密保存。

### 导入后为什么应用还没有运行？

导入只创建期望配置，不创建构建记录、发布记录或 Kubernetes 工作负载。请先检查仓库、镜像和运行配置，再手动构建和发布。
