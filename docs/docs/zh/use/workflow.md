# 平台功能怎么配合

Luna DevOps 把代码、镜像、集群和访问入口连接成一条交付路径：

```text
项目空间 → 应用 → 部署配置 → 构建 → 发布 → 访问入口
```

第一次部署可以参考[部署上线一个 Web 项目](/start/first-project)。

## 1. 项目空间

项目空间是团队、权限和资源的边界。成员、应用、构建、发布和访问入口都归属于项目空间。通常可以按产品、团队或客户划分。

添加成员时应从平台用户中选择，并按实际职责授予最小权限。

## 2. 应用

应用代表一个可独立部署的服务。一个仓库可以拆成多个应用，例如 API、Web 和 Worker。

应用拓扑可以查看当前工作负载及其依赖关系。项目空间还可以记录应用之间的关系；服务引用可能改变源服务下一次发布时的配置。删除被其他服务引用的应用前，必须先处理引用关系。

项目空间的应用列表会按开发、测试、预发、生产等部署阶段分别显示运行状态和当前就绪副本数 / 期望副本数，不会把多个阶段的副本合并成一个总数；尚未创建实际工作负载的应用显示“未部署”。该状态来自运行集群的实时观察，上游暂时不可达时会明确显示不可用，而不会沿用旧状态。

## 3. 部署配置

部署配置决定应用从哪里构建、如何运行以及发布到哪个集群。首次创建时重点确认：

- 来源：代码仓库或已有镜像。
- 环境阶段和目标运行集群。
- 镜像站与镜像地址。
- 服务端口、CPU、内存和副本数。
- 环境变量、Secret、配置文件和数据卷。
- 构建成功后是否自动发布。

新建部署配置未填写阶段时使用 `dev`。阶段在创建后不可修改；`sys-*` 只用于平台管理的既有组件。

建议先用已有镜像验证运行和访问链路，再接入 Git Provider 与自动构建。

## 4. 构建与发布

构建把代码生成镜像，发布把选定镜像部署到运行集群。发布后应检查 Release、工作负载、日志和健康状态，不能只以任务“已提交”作为完成依据。

部署页的运行状态以 `n/m` 展示同一次 Kubernetes 观察中的就绪副本数和期望副本数，例如 `2/3` 表示 3 个期望副本中有 2 个已经就绪。发布状态只表示 Release 工作流的历史结果，不附带当前副本数；“发布成功”不等同于当前运行实例就绪。

部署配置列表用 `CPU · 内存` 展示运行规格，并在“域名”列显示同命名空间可直接访问的 Kubernetes Service 名称。通过行末三点菜单的“查看详情”可打开右侧详情面板，查看命名空间内 Service、跨命名空间完整域名、项目访问地址、实时资源占用和当前发布信息。

启用自动伸缩后，页面中的运行费用是按配置副本数计算的基准预估，不是实时费用。实时状态中的期望副本数可能因 HPA 改变；HPA 最小副本数可以设为 `0`，此时页面以中性“已缩容 · 0/0”表示工作负载已观察到但当前没有运行实例，不会显示为绿色“就绪”。观测不可用时不展示 `0/0`，避免把缺失数据误解为真实零副本。

配置或镜像变化后需要创建新 Release。使用不变的镜像 Tag 会增加版本判断和回滚难度，生产环境建议使用可追溯的唯一 Tag。

编辑已有运行实例的部署配置时，修改副本与资源规格、镜像、Service/HPA、运行配置、数据卷、高级 Kubernetes 配置或部署阶段 Hook 后，表单底部会提示这些变化需要重新部署，并提供“仅保存”和“保存并重新部署”。名称、构建参数、自动部署与审批策略、Web Console 等不会改变当前实例的设置只需保存，不会显示重新部署操作。是否存在运行实例以运行集群的实时期望副本数为准；已缩容到零或尚未部署的配置不会显示该提示。

## 高级运行配置

大多数服务可以保留默认值。只有应用确有需要时，再配置健康检查、启动命令、StatefulSet、自动伸缩、调度规则、安全上下文、辅助容器和高级存储选项。

普通环境变量和 ConfigMap 引用在表单中使用每行 `KEY=VALUE` 编辑。API 会把运行时环境变量明确标记为 `public` 或 `secret`；普通值只写入 ConfigMap，密钥值只写入加密存储。平台不会根据字段名或内容猜测敏感性，也不会阻止你把任意键保存为普通变量；选择 `public` 后，该值会作为普通配置保存并可由有权客户端读取。需要加密且不回显的值请自行选择运行时密钥。同一个键可以暂时同时保留普通值和密钥值，发布运行时密钥始终覆盖同名普通值；清除密钥后，保留的普通值会重新生效。

运行时密钥与普通配置、密钥文件分开管理：请先保存部署目标或运行配置集，再在“运行时密钥”区域按键值行添加、替换、生成或清除字段。密钥按钮只执行当前密钥操作，不会提交或关闭外层部署配置表单。替换时留空不会改变原值，删除必须使用明确的“清除”操作。每次密钥变更都会整体成功或整体回滚；替换或清除成功后，平台会移除已不再引用的旧密钥。密钥值始终保持掩码，API、个人访问令牌和 AI 助手都不会返回密钥明文。

持久数据先在项目空间的[数据卷中心](./project-volumes.md)创建或引用，再由部署配置选择稳定的数据卷。每个挂载按标识、来源、路径和来源详情填写；在窄屏或较窄的配置窗口中，这些字段会自动纵向排列。PVC 的存储类型通常只能在创建时确定；`emptyDir` 数据会随 Pod 销毁，也不包含在数据导出中。

删除应用或部署配置只会解绑项目数据卷，不会改变卷的项目归属或自动删除 PVC。只有在数据卷详情中完成影响预检、明确选择永久删除并通过二次验证后，平台才会删除托管 PVC；操作前建议先[导出归档](./volume-transfer.md)。

公共配置可以选择跟随最新值或保存快照。部署钩子适合数据库迁移等一次性步骤；失败的钩子可能阻止发布继续，请确保脚本可重复执行并准备回滚方式。

## Web Console 与数据导出

Web Console 是否可用受项目设置、账号权限和 MFA 策略限制。终端操作会被审计，不应在终端中输出或粘贴不必要的密钥。

数据导出在数据卷详情中创建异步 Transfer，需要项目 Owner/Admin 权限和必要的二次验证。浏览器会在当前页面换取短期下载会话并支持断点续传。导出不包含 `emptyDir`；任务必须进入成功终态后才算完成。详见[导入与导出数据卷](./volume-transfer.md)。

## 访问入口

访问入口把域名、路径和 TLS 连接到应用服务。创建后应检查下发状态、域名解析、Service 端口和应用健康状态。

### TLS 选择

| 场景 | 推荐模式 |
| --- | --- |
| CDN 或外层代理已经处理 HTTPS | 上游代理已终止 TLS |
| 集群 Gateway 使用已有证书 | Gateway 终止 TLS |
| 使用 cert-manager HTTP-01 | HTTP Challenge 证书 |
| 使用 DNS-01 通配符证书 | 在集群中配置通配符证书 |

平台只使用运行集群中已经配置的 Gateway、Issuer 和证书资源，不会自动创建 ACME 账号或 DNS Provider 凭据。

如果 OIDC 等应用生成了错误的 `http` 回调地址，应检查 CDN、反向代理和 Gateway 是否正确传递外部协议。修改转发头或 TLS 链路可能影响所有入口，请由平台管理员评估后操作。
