# 运行时与部署工作流

## 准备部署

- 按需明确项目空间、应用、目标集群或环境、镜像或发布来源、资源规格、副本数、暴露端口、运行时变量和密钥引用。
- 目标集群、环境和现有配置先按根 Skill 直接索引的 `resource-resolution.md` 解析。唯一且
  可用、兼容的候选直接采用；只有多个有效候选无法消歧时才要求用户选择。
- 要求用户输入标识符前，先发现候选集群和现有配置。
- 使用 `send_message` 展示目标选项；不要仅为记录选择而跳转到集群或项目页面。
- 区分部署、重新部署、重启、扩缩容、回滚和配置更新，不得互相替代。
- 创建部署配置前读取应用已有配置，避免为同一阶段重复创建。区分仓库来源和镜像来源，
  并按来源只显示相关字段。
- 配置变化只修改期望状态；运行中的 Pod 需要新 Release 或对应重启流程才会应用。

## 运行集群

- 管理员连接集群时收集名称、Kubeconfig、默认命名空间策略、域名后缀、Gateway 与
  证书策略；Kubeconfig 只通过受控 Secret 字段提交。
- 保存后执行连接测试，并读取集群实时资源或系统组件确认权限范围。创建记录成功但
  连接测试失败时，状态是配置未就绪。
- 更新或删除集群前读取其项目、部署配置和系统组件引用；删除属于高影响操作。
- 资源浏览、YAML、事件和 Pod 终端用于诊断，不得通过终端绕过平台已有业务操作。

## 配置与数据

- 运行变量按项目配置集、部署级覆盖和 Secret 引用分层；明确跟随引用或快照语义。
- 持久化数据统一使用项目空间数据卷中心。部署配置只引用可信工具结果中的
  `projectVolumeId`；临时目录使用 `emptyDir`。不要让用户在部署表单中直接填写 PVC 名，已有
  PVC 必须先在数据卷中心选择“引用”或“纳管”。
- 创建或选择数据卷前确认目标集群、StorageClass、访问模式和卷模式。Filesystem 卷使用
  `mountPath`；Block 卷使用 `devicePath`。扩容只能增加容量，变更 StorageClass、访问模式或
  卷模式需要创建新卷并迁移数据。
- 数据卷删除必须先调用 `previewProjectVolumeDeletion`。托管卷使用 `dataAction=delete`，引用卷
  使用 `dataAction=detach`；存在挂载或运行中 Transfer 时不得绕过阻断。
- 导出前确认数据卷状态、一致性模式、用户角色和 Step-up MFA。任务进入 `queued/running`
  不代表完成，必须用 `getVolumeTransfer` 回读到 `succeeded`。下载票据、Range 会话和本地文件
  传输由 Web/CLI 处理，Agent 不调用上传/下载协议端点。
- 导入本地 `tar.gz` 或 `raw.zst` 时，引导用户通过 Web 或 Luna CLI 选择文件；不要读取本地
  文件、把文件内容编码到工具参数，或声称仅创建 Import 记录就已导入成功。
- Web Console 和命令执行必须遵守项目开关、角色、MFA 与审计，不把终端当普通读工具。
- 只有连续诊断确实需要保留工作目录或环境变量时，才按 `application-diagnostics.md` 的流程创建、复用
  并显式关闭运行命令会话；单条独立检查仍使用一次性命令。会话创建成功不代表后续命令已获授权。

## 安全执行

- 提议敏感或破坏性操作前，概括实质性变更。
- 让平台批准和 MFA 界面对已注册调用进行门控。
- 保持参数绑定：目标、镜像、副本数或配置发生变化时，必须创建新提议。
- 不得声称排队中或运行中的发布已经完成。

## 验证与恢复

- 可用时检查发布、工作负载、Rollout、Pod 和事件状态。
- 区分调度或容量、镜像拉取、配置、密钥、健康检查、崩溃循环、超时和基础设施失败。
- 回滚时，识别真实存在的上一次成功发布或镜像 Digest，并说明将恢复的状态。
- 对缩容到零、删除、强制重启或回滚，明确影响并依赖平台二次确认。
- 部署成功后，根据用户最可能的下一目标提供运行时状态、日志或事件、网关设置或发布检查。
- 创建或更新部署配置：回读来源、集群、阶段、端口、资源与有效运行配置。
- 创建 Release：确认 revision、镜像、投递状态、Rollout 与 Pod 就绪；超时、流断开和
  `deploying` 不是成功。
- 重启：确认产生新的 Pod Template 指纹或 Pod，并恢复就绪。
- 回滚：确认选择真实历史成功 revision，新的 Release 与工作负载都运行该版本。
- 删除：先读取删除影响。默认保留平台托管 PVC；用户明确永久删除时先建议导出，并依赖
  平台批准。随后确认业务记录、受管工作负载与数据处理状态达到终态；若服务引用阻止删除，先处理引用。
