# 构建与发布

## 从源码构建

构建会读取绑定的代码仓库，根据 Dockerfile 生成镜像并推送到镜像站。开始前确认：

- Git 凭据可以读取仓库和目标分支。
- 镜像站凭据包含推送权限。
- 构建参数中没有明文 Secret；敏感值使用密钥变量。

若镜像站显式引用的推送凭据或构建关联的部署目标已经不存在、当前用户无权使用或查询失败，构建会直接失败，不会自动改用其他凭据或默认目标。修复引用后再重新构建。

启动构建后查看日志，直到任务进入成功、失败、超时或已取消终态。失败、超时和取消的构建会在构建列表的状态下方显示原因摘要，完整输出在“日志”中查看。运行中的构建会显示当前阶段和 Dockerfile 指令的完成进度，例如“运行构建命令 第 4/8 步”；命中缓存的步骤计为已完成。多阶段构建的后续阶段开始执行时才计入总数，因此总数可能在构建过程中增加。建议为生产镜像使用唯一、可追溯的 Tag，例如在目标镜像中写 `{short_sha}`。

目标镜像和 Tag 可用的变量见[镜像仓库路径与 Tag 模板](../../reference/image-templates)；Build Args 格式、构建变量优先级和钩子环境变量见[构建参数与构建变量](../../reference/build-variables)。

构建有两个时限：执行时间超过构建超时（部署配置或 `BUILD_JOB_TIMEOUT_SECONDS`）会被标记为“已超时”，平台会删除对应的构建 Job 并结算已用时长；排队时间超过构建超时的两倍仍未开始，也会标记为“已超时”，原因显示为排队时间过长。项目空间或部署配置正在删除时不能再触发构建。

## 发布

发布会把选定镜像部署到运行集群。创建 Release 后检查：

1. Release 已进入成功终态。
2. 工作负载的就绪副本达到期望副本，例如 `2/2`。
3. 容器日志和健康检查正常。
4. Service 在集群内可以访问。

> “发布成功”只表示发布流程完成，不保证应用当前仍然健康。运行状态以集群实时观察为准；集群不可达时平台会显示“不可用”，不会用旧状态代替。

看板、应用列表和应用详情使用同一套运行状态：只统计已启用且至少成功发布过一次的部署配置，并展示其中最需要关注的状态；已停用的部署配置显示“已停用”，从未成功发布的显示“未部署”，二者都不影响应用整体状态。“当前版本”是现存部署配置上最近完成的一次成功发布。

发布失败或被取消时，部署列表的“当前版本”会在状态旁显示原因摘要，点击“查看日志”查看发布过程的完整输出。

### 取消发布

排队中或进行中的发布可以在部署配置的操作菜单中选择“取消发布”，需要发布权限。取消后平台停止该发布的后续步骤，发布显示为“已取消”。

- 取消不会回滚已经下发到集群的资源；需要恢复上一版本时使用“回滚”。
- 重复取消同一个已取消的发布不会产生新的变化；已成功或已失败的发布不能取消。

发布从开始执行起超过总时限（`DEPLOY_ROLLOUT_TIMEOUT_SECONDS` 与 30 分钟中的较大值的两倍，默认 1 小时；仍在排队的发布从创建时计算）仍未结束时，会被标记为失败，原因显示为超过发布总时限。运行集群长时间不可达时也以此结束发布。

## 自动交付

需要自动交付时，再开启构建成功后自动发布或仓库 Webhook。首次上线建议保留手动步骤，确认每一段都正常后再自动化。

仓库 Webhook 以代码仓库账号的所有者身份触发构建，并在每次推送时重新检查：所有者仍是项目空间成员且具备触发构建的权限、项目空间未在删除、余额策略允许新构建。检查未通过时不会创建构建，平台会在事件中心记录“Webhook 构建被拒绝”事件和原因代码。Git 平台重复投递同一个事件（相同的投递 ID）时只会创建一次构建。

### 连续提交时的构建顺序

前一个构建还没结束又触发了新构建时，按部署配置“发布与触发”中的**构建并发策略**处理。该选项只对源码构建的部署配置显示，对手动构建和 Webhook 构建同样生效。

| 策略 | 行为 |
| --- | --- |
| 按顺序排队（默认） | 同一部署配置的构建按触发顺序逐个执行，前一个结束后才开始下一个。 |
| 取消进行中的旧构建 | 新构建开始时，取消同一部署配置更早的排队中和运行中构建，原因显示为“已被更新的构建取代”。 |
| 并行执行 | 同一部署配置的构建同时执行。 |

- 无论哪种策略，同时运行的构建总数还受项目空间（默认 2）和运行集群（默认 4）的构建并发上限约束。
- 排队时间仍受上面的排队时限约束：短时间内连续提交多次时，排在后面的构建可能因排队时间过长而超时，此时可改用“取消进行中的旧构建”。
- 开启自动发布时，如果同一部署配置更新的构建已经发布，较早的构建即使后完成也不会自动发布，避免回退到旧镜像。
