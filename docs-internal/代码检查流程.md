# 代码健康检查 SOP

本文件只定义检查频率、判定方法和报告格式。工程硬约束以根 `AGENTS.md` 为准，前端细则以
`web/AGENTS.md` 为准，具体门禁以 CI、`scripts/ci/` 与 `scripts/release-check.sh` 为准。

## 1. 范围门

开发者当前指令、范围和验收标准是需求权威。检查开始时记录代码基线、工作树、允许修改的范围和
未覆盖范围；分析/审查默认只读，实施只覆盖已授权问题及其真实调用链。

拟新增机制前只问三件事：

1. 当前指令是否明确要求？
2. 现有硬约束、真实调用方、数据流或确定失败路径是否要求？
3. 不实现是否会让本轮验收失败或产生错误结果？

三项都没有证据时不实施，也不写入接口、测试、文档或 TODO。只有结果会因选择而显著不同，且无法
从仓库事实确认时，才向开发者提出方案。

## 2. 检查频率

### 每次改动

- 检查工作树和实际 diff，确认没有覆盖用户改动或带入构建产物。
- 沿真实入口核对参与的 Web、API、Worker、Agent、数据库和外部 Provider。
- 按风险执行就近测试或完整门禁，核对 i18n、权限、Secret、实时状态、可观测、迁移和文档。
- 只记录尚未解决且开发者确认需要跟踪的事项；完成记录由测试和版本历史保存。

### 双周结构检查

- 查看近期高频修改和大文件，寻找职责堆积、重复规则、旧模型、技术型目录与跨域反向依赖。
- 对齐模型、迁移、OpenAPI、前端类型、任务载荷、Kubernetes 标签和公开文档语义。
- 检查公共组件/接口是否仍有多个真实消费者，单实现策略层和纯转发 facade 是否仍有价值。
- 核对列表、表单、状态、外部平台适配、实时观察和权限是否复用权威路径。

### 每月设计复盘

按项目空间与权限、应用部署、构建 Worker、集群、网关证书、计费、AI、迁移和文档逐域复盘。
每轮只报告证据最强的一个或两个问题；产品模型或职责边界需要重做时，先提交影响、迁移和验收方案，
获得授权后再实施。

## 3. 专项检查

### 3.1 冗余与过度设计

- 无消费者文件、字段、配置、依赖、资产、索引、状态、测试夹具和文档。
- 单一实现却保留 interface/provider/strategy/factory，或纯转发 wrapper、alias、barrel、bridge。
- 为未发布旧行为或假设未来需求保留兼容层、fallback、插件点、缓存、队列、lease 和多态解析。
- 同一事实由数据库、配置、OpenAPI、前端类型或文档重复维护。
- 测试只为自证虚构分支、内部实现或复制文案，而非用户可观察行为与真实边界。

删除前必须证明没有生产消费者；有消费者时先切换到权威路径，再删除旧层。

### 3.2 过度防御

重点搜索 `try*`/`safe*` wrapper、宽泛 `recover/catch`、nil 依赖、空对象、默认成功、静默降级、
重复校验、无界重试和“不可能状态”的 fallback，并逐项回答：

- 输入是否真的来自不可信外部边界？
- 并发、权限、Secret、资源释放或上游失败是否真实存在？
- 防御是否保留错误语义、审计、Trace 和最终一致性，还是吞错并制造假成功？
- 类型、构造器、数据库约束或单一入口能否直接消除该分支？

保留真实的安全、并发、I/O、外部输入与清理防御；删除只掩盖无效内部状态、重复上游保证或让系统继续
运行在错误依赖上的保护。不得为了减少行数把 fail closed 改成 fail open。

### 3.3 安全与实时状态

- 权限、租户边界、Webhook 签名、Secret、Token、构建网络、发布凭据和危险操作审计必须服务端验证。
- 当前健康、数量、指标和存在性从 Kubernetes/外部平台读取；数据库只保存配置、引用和历史。
- 上游不可达返回 `unavailable` 和稳定 code，不使用旧缓存冒充实时事实。
- 认证与发布检查按 P0/P1/P2 分级；P0 阻断，P1 在候选版本前修复或显式接受，P2 只在确认后进入 TODO。

### 3.4 数据、契约与可观测

- 数据库 DDL、索引、约束和一次性回填只由编号迁移交付；验证单一 `000103_baseline` 能在空 PostgreSQL 上完成
  up、down、reapply，并覆盖最终 Schema、种子数据、dirty 状态和未版本化非空库拒绝。
- OpenAPI、模型、前端适配、Agent catalog、异步载荷和错误码在同一事项同步。
- 沿 HTTP/SSE/WebSocket、数据库、Redis、任务、Provider、模型和工具边界检查 Trace Context、
  失败 Span、关联日志、低基数 Metric 与敏感字段排除。
- i18n 检查必须发现缺 key、语言结构/插值不一致、缺 bundle 和未覆盖 lazy locale；动态 key 豁免
  只能精确对应真实调用。

### 3.5 测试取舍

测试用于阻止可信回归，不用于证明每一行代码都被执行。新增测试前必须能回答：它保护哪个用户可观察行为、
跨边界契约或高风险不变量；生产代码发生什么错误时会失败；为什么现有静态检查或更接近事实源的测试不能发现。
无法回答时不新增，不以统一行覆盖率目标驱动用例数量。

下列情况必须测试：

- 条件分支、边界值、状态转换和真实发生过的缺陷；缺陷回归用例应能在修复前失败。
- 权限与租户隔离、Secret/Token 不泄露、输入校验、账务、审计、幂等、并发、取消、重试与资源释放。
- HTTP/SSE/WebSocket、数据库、Redis、Kubernetes、文件系统和外部 Provider 的序列化、错误映射及失败终态。
- OpenAPI、迁移、异步任务载荷、CLI 机器输出与发布产物等跨进程契约；生成物优先使用生成后 diff 门禁。
- 用户完成关键动作所需的交互结果、请求或副作用，以及加载、错误、空状态、键盘操作和异步清理。

下列情况通常不写自动化测试：

- 编译器已证明的类型、无分支 getter/透传、一行包装、常量与自身的比较，以及语言、标准库或第三方组件的既有行为。
- 非契约性的精确文案、Tailwind/CSS class、`data-slot`、DOM 层级和静态 children；布局、色彩和响应式效果交给浏览器或视觉验收。
- 同一规则仅替换字段名或文案的笛卡尔枚举；每类等价输入保留一个代表和真实边界即可。
- Mock/Fake 自身的业务正确性、私有调用次数和实现顺序；测试替身需要约束时复用同一份 conformance suite。
- 已被 lint、typecheck、生成物漂移检查或更权威集成测试以相同失败信号稳定覆盖的断言。

测试层级遵循“能证明风险的最低有效层”：语法与目录约束放 lint/static check，有分支的纯转换放单元测试，
React 测用户交互且只 mock 网络边界，Handler/Service/Provider 协作放集成测试。SQL、事务锁、迁移和数据库
约束使用真实 PostgreSQL；Kubernetes 与流协议至少保留 provider/transport 契约测试；E2E 只覆盖少量关键旅程。
共享规则在权威层完整测试一次，上层最多保留一条连通性 smoke，不逐层复制同一断言。

删除测试前先建立“风险 → 测试”映射。只有用例没有独有失败模式，或同一失败已由更接近事实源的门禁覆盖时
才删除；权限、安全、并发、迁移和发布产物测试不得按体积裁剪。Flaky 测试必须修复隔离、时钟或等待条件，
不得靠重试转绿。每个测试文件必须被至少一个本地标准命令和 CI job 实际发现；门禁变更时核对发现的文件与
用例数量，避免孤儿测试。

## 4. 分级与处理

- **保持观察**：证据成立但影响低，不立即修改；开发者确认后才进入 TODO。
- **局部重构**：边界清楚、可独立验收，直接删除重复或恢复单一事实源，并补针对性测试。
- **重新设计**：改变产品模型、公开 API、持久数据或关键职责；先写迁移、兼容、回滚和验收方案，
  获得授权后拆为独立任务。

发现问题不等于获得全局重写授权。实施顺序始终是固定基线、定位消费者、切换权威路径、删除旧层、
验证成功/失败链路、记录剩余风险。

## 5. 报告模板

```md
## YYYY-MM-DD 代码健康检查

- 范围与原因：
- 基线与环境：
- 验证命令及结果：
- 发现：模块 / 证据 / 影响 / 分级 / 建议
- 已实施：
- 进入 TODO：
- 未审计范围与已接受风险：
```

“本轮完成”只表示声明范围内已验证，不代表未审计区域安全或项目已通过发布签字。
