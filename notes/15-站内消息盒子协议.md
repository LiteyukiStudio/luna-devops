# 站内消息盒子协议

本文冻结 Luna DevOps 第一版站内消息盒子的跨模块契约。实现可以拆分，但不得绕过这里定义的用户隔离、状态机、i18n 和业务动作边界。

## 1. 能力边界

- `PlatformEvent`：记录不可变的平台事实，不承担个人已读状态。
- `NotificationDelivery`：记录 SMTP、Webhook 等外部渠道投递，不承担站内消息。
- `InboxMessage`：面向单个用户的站内消息，保存已读、归档和聚合信息。
- `ActionRequest`：需要指定用户决定的业务请求；消息只引用请求，不直接保存或执行任意 HTTP 操作。

站内消息是强制的一方能力，不作为可禁用的通知 Channel。只有目录中明确允许进入消息盒子的业务事实才投影为消息，禁止把全部 Platform Event 自动灌入消息盒子。

## 2. 稳定枚举

### 2.1 消息

- `category`：`action`、`project`、`billing`、`security`、`delivery`、`system`
- `priority`：`low`、`normal`、`high`、`critical`
- 消息状态不保存枚举，通过 `read_at`、`archived_at` 派生。

### 2.2 请求

- `status`：`pending`、`processing`、`completed`、`rejected`、`cancelled`、`expired`、`failed`
- `type` 第一批：`project.billing_owner_transfer`
- `decision` 第一批：`accept`、`reject`

`read_at` 与请求状态相互独立；标记已读、全部已读或归档不得执行、接受或拒绝请求。

## 3. 持久化模型

### 3.1 inbox_messages

```text
id text primary key
recipient_user_id text not null index
type text not null index
category text not null index
priority text not null index
actor_id text not null default ''
project_id text not null default '' index
resource_type text not null default ''
resource_id text not null default ''
title_key text not null
content_key text not null
params_json jsonb not null default '{}'
action_request_id text not null default '' index
deep_link text not null default ''
group_key text not null default ''
dedup_key text null
read_at timestamptz null
archived_at timestamptz null
expires_at timestamptz null
created_at timestamptz not null
updated_at timestamptz not null
```

唯一索引：`dedup_key` 非空时唯一。`deep_link` 只允许站内绝对路径，服务层拒绝协议、双斜线和反斜线。

### 3.2 inbox_action_requests

```text
id text primary key
type text not null index
requester_user_id text not null index
recipient_user_id text not null index
project_id text not null default '' index
resource_type text not null default ''
resource_id text not null default ''
payload_json jsonb not null default '{}'
status text not null default 'pending' index
row_version bigint not null default 1
expires_at timestamptz null
responded_at timestamptz null
created_at timestamptz not null
updated_at timestamptz not null
```

动作决定必须使用 `recipient_user_id + status + row_version` 条件更新。执行前重新检查收件人、期限、发起人权限和目标资源现状。

## 4. Go 服务契约

包：`internal/inbox`

```go
type PublishInput struct {
    RecipientUserID string
    Type string
    Category string
    Priority string
    ActorID string
    ProjectID string
    ResourceType string
    ResourceID string
    TitleKey string
    ContentKey string
    Params map[string]any
    ActionRequestID string
    DeepLink string
    GroupKey string
    DedupKey string
    ExpiresAt *time.Time
}

func (s Service) Publish(ctx context.Context, input PublishInput) (model.InboxMessage, bool, error)
func (s Service) CreateActionRequest(ctx context.Context, input CreateActionRequestInput) (model.InboxActionRequest, error)
func (s Service) UnreadCount(ctx context.Context, userID string) (int64, error)
func (s Service) MarkRead(ctx context.Context, userID, messageID string) error
func (s Service) MarkAllRead(ctx context.Context, userID string) error
func (s Service) Archive(ctx context.Context, userID, messageID string) error
```

所有数据库调用使用传入 Context。服务记录低基数 OTel operation，并在发布、去重、决定成功和决定失败等关键节点输出稳定结构化事件。

## 5. HTTP 协议

基础路径：`/api/v1/inbox`

```text
GET  /                         分页列表
GET  /unread-count             未读数量
GET  /:messageId               单条详情
POST /:messageId/read          标记已读
POST /read-all                 全部标记已读
POST /:messageId/archive       归档
POST /action-requests/:requestId/decision
GET  /stream                   SSE 变更提示
```

计费归属转移由项目业务域发起，不通过通用消息接口拼装：

```text
POST /api/v1/projects/:projectId/billing-owner-transfer-requests
```

请求体：`{"recipientUserId":"usr_..."}`。响应返回创建的 ActionRequest；重复未完成请求返回 `409`。

列表参数：

```text
page pageSize sortBy sortOrder
filter=all|unread|action
category=action|project|billing|security|delivery|system
```

分页响应沿用 `items/page/pageSize/sortBy/sortOrder/total/totalPages`。消息响应额外包含：

```json
{
  "actionRequest": {
    "id": "iar_...",
    "type": "project.billing_owner_transfer",
    "status": "pending",
    "rowVersion": 1,
    "expiresAt": null,
    "allowedDecisions": ["accept", "reject"]
  }
}
```

决定请求：

```json
{ "decision": "accept", "expectedVersion": 1 }
```

SSE 只推送失效提示，不作为事实源：

```text
event: inbox.changed
data: {"unreadCount":3,"messageId":"imsg_..."}
```

断线后前端重新请求列表和未读数量。第一版允许进程内订阅；多 API 实例的 Redis 广播作为后续增强，数据库始终是唯一事实源。

## 6. 前端协议

- Topbar 使用铃铛图标和 `1..99 / 99+` Badge。
- 桌面端使用右侧 Popover；移动端使用 Sheet。
- 快捷分类：`all`、`unread`、`action`。
- 浮层最多显示最近 10 条，底部进入 `/inbox` 完整页面。
- 行点击标记已读并跳转 `deepLink`；待处理请求进入详情，不在紧凑行内直接执行高风险动作。
- 所有 UI 常量使用 i18n。`titleKey/contentKey` 由前端白名单映射，未知 key 使用安全的通用文案并展示原始资源标识，不渲染后端 HTML。
- 全部标记已读不影响 ActionRequest 状态。

## 7. 第一批消息目录

| type | category | priority | 行为 |
| --- | --- | --- | --- |
| `project.member_added` | project | normal | 成员直接生效后告知目标用户 |
| `project.member_role_changed` | project | high | 告知目标用户角色变化 |
| `project.member_removed` | project | high | 告知目标用户被移出 |
| `project.billing_owner_transfer_requested` | action | high | 创建待处理请求 |
| `project.billing_owner_transferred` | billing | high | 向双方告知结果 |
| `system.announcement` | system | normal | 平台公告，第一版只保留服务接口 |

## 8. 计费归属转移验收规则

- 只有当前计费归属人本人且仍为项目 Owner 时可以发起，其他 Owner 不能转移他人的计费责任。
- 目标用户必须是未禁用的项目成员，且不能是当前计费用户。
- 同一项目同时只允许一个未完成的转移请求。
- 接受时重新验证发起人仍为 Owner、目标用户仍是成员、项目当前计费用户未变化。
- 接受成功只影响未来费用；历史用量、账本和余额不迁移。
- 接受、拒绝、过期、取消和失败均写 AuditLog；成功同时写 PlatformEvent 和双方 InboxMessage。
- 所有写入和计费归属更新在同一数据库事务内完成。

## 9. 模块文件边界

- 持久化核心：`internal/model/inbox.go`、`internal/inbox/**`、迁移和核心测试。
- HTTP/SSE：`internal/api/inbox_*`、`internal/api/router.go` 和 Handler 测试。
- 前端：`web/src/api/domains/inbox.ts`、消息组件、`/inbox` 页面和 i18n。
- 业务接入：项目成员 Handler、计费归属转移 Handler、事件/审计，由主线程负责。

模块不得跨边界修改其他模块实现；如协议不足，先报告主线程调整本文，再继续编码。
