# 使用内嵌 AI 助手

Luna DevOps AI 助手用于解释构建、发布、Pod、Gateway、证书与通知问题，并把分散在多个页面的状态整理为一条可恢复的诊断时间线。它代表当前登录用户工作，不拥有额外权限，也不会绕过项目角色、OAuth Scope 或 Step-up MFA。

## 打开助手

只有部署开关、站点开关、Agent 健康、模型配置、成本限制与当前用户权限同时满足时，登录后的控制台才会显示助手入口。能力未知、Agent 不可用或任一配置缺失时，入口不会出现。

桌面端使用可拖动和调整尺寸的悬浮窗口；移动端使用全屏界面。悬浮球支持拖动，窗口尺寸、窗口位置和悬浮球位置都会保存在当前浏览器中，并在刷新后恢复；视口变化时会自动约束在可见区域。关闭窗口、刷新页面或网络断开只会停止当前浏览器订阅，不会取消已经持久化的运行。

顶栏最左侧的列表按钮用于打开会话列表；右侧只保留“新建会话”和关闭按钮，使导航入口与当前会话操作保持清晰分组。关闭后助手恢复为可拖动悬浮球，不再提供语义重复的独立缩小状态。顶栏的“新建会话”和会话列表中的同名入口行为一致。切换会话时，每个会话分别保留草稿、流式时间线、运行状态和 SSE 订阅；一个会话仍在生成时，可以切换到另一个会话继续提问。会话列表会同时标记所有正在生成的会话，而不是只显示当前会话。

会话列表提供独立的批量选择模式。进入后可以逐项选择、全选并一次确认删除多个会话；退出选择模式会清空临时选择，普通浏览状态不会常驻复选框。批量删除中的每个会话仍按当前登录用户做所有权校验。

输入框使用 Enter 发送、Shift+Enter 换行。中文、日文等输入法仍处于候选组合状态时，Enter 只确认候选词，不会提前发送消息；组合输入结束后再次按 Enter 才会发送。

## 阅读时间线

时间线把内容分成三类：

- **Thinking**：只展示模型允许公开的思考摘要，或明确标记为“执行进度”的平台状态。原始隐藏推理不会展示。
- **Message**：用户输入和助手最终回答。
- **Tool Call**：助手调用平台能力的记录。默认折叠，折叠行只显示工具名称和右侧状态 Badge；展开后显示经过脱敏的参数、结果、状态和耗时。会话自动命名等内部维护工具不进入用户时间线。

时间线先按 `turnId` 归并为用户轮次。每轮用户消息只显示一次，随后只有一个助手回复容器；该容器内部再按持久 `timelineIndex` 原样排列 Thinking、阶段性 Message、Tool Call 和最终 Message。模型在工具调用前后的多段文本不会被拆成多个独立助手气泡，流式更新和历史快照也保持相同拓扑。

用户与助手气泡分别靠右、靠左排列，最大宽度限制为消息区的 78%，始终为对方一侧保留可辨认的留白。短消息按内容收缩；表格、代码和工具详情仍只在助手气泡内部处理溢出。

Tool Call 只有在真实 `running` 状态下显示旋转加载图标；失败、成功、取消、跳过、等待批准和等待 MFA 使用各自的静态语义图标，避免把终态误看成仍在执行。

模型响应通过可恢复 SSE 逐段显示，不需要等待完整回答生成后再一次性出现。生成首个文本片段前显示三点波浪指示器；开始输出后，Message 会按增量自然增长。正在更新的 Thinking 使用字号更小的紧凑三行视窗并跟随最新摘要，完成后自动收起；用户向上滚动后会暂停自动跟随，可以随时回到最新位置。

助手回答使用紧凑消息气泡，并按 GitHub Flavored Markdown 渲染标题、段落、列表、引用、链接、代码块和表格。回答提到平台注册页面或已有资源时，Agent 会根据内置导航 Skill 输出 `[显示名称](/站内路径)`；前端把已注册的站内路径渲染为主色链接，并通过 React Router 无刷新跳转。未知站内路径、协议相对地址和脚本协议不会变成可点击链接，外部 HTTP(S) 链接仍在新标签页打开。

小窗和消息时间线只允许纵向滚动；表格与代码块在自身边界内独立横向滚动，不会撑宽助手窗口或带动整段对话左右移动。模型返回的原始 HTML 和外部图片不会直接执行或加载。

## 页面联动

普通回答中的站内 Markdown 链接用于直接引用正在讨论的页面或资源；结构化 `create_options` 用于提供多个可选下一步。两者共用同一平台注册路径边界，链接本身只负责导航，不代表访问已授权或业务操作已执行。

部分 Tool Call 会提供“打开发布事件”“查看 Pod”或“切换到部署 Tab”等操作。这些操作通过前端注册的声明式 UI Action 执行，只能使用平台路由、Tab、筛选器与对话框白名单，不能执行任意脚本、DOM Selector 或外部 URL。

表单预填只会填写允许的非密钥字段，不会自动保存。保存仍通过普通业务 API、权限检查和审计。

## 批准与 MFA

普通读取和低风险写入会在 Luna API 以当前登录用户身份重新鉴权；有权限时直接执行，无权限时返回稳定的拒绝状态。敏感、破坏式或工具目录显式标记为需要批准的高风险操作才会暂停运行并展示：

- 具体工具和操作类型；
- 目标项目空间、应用、环境或资源；
- 已绑定的完整参数；
- 预计影响与风险等级。

用户可以选择“同意”“拒绝”或“全部同意”。批准只对当前参数哈希和版本有效，参数变化后必须重新批准；“全部同意”只覆盖当前 Run 中已经展示且仍在等待批准的调用，不包含未来调用、其他会话或变更后的参数。需要 Step-up MFA 时，批准不能代替 MFA；验证完成后运行才会重新排队并从检查点继续。

助手也可以通过结构化选项询问下一步。选项可以发送一条新消息、打开平台注册页面，
或请求一个受控工具操作；最后一种仍会重新进入工具策略、参数校验、批准和 MFA
流程，点击选项本身不会直接执行危险操作。

`create_options` 是纯 UI 工具，不读取或修改业务数据。每个正常完成的回复都会包含一次用户意图预测：Agent 按当前问题、最近 6 轮对话、页面上下文和可信工具结果生成 2-5 个下一步选项，并把经过 Schema 校验的标题、说明和选项原样保存到 Timeline，再通过 SSE 发送给前端。前端将其显示为始终可见的“建议下一步”按钮，而不是藏在默认折叠的普通 Tool Call 中。若 Provider 没有按约定返回该工具，Agent 会进行一次强制结构化预测；Provider 仍不兼容时才使用与当前路由匹配的安全兜底，避免一个已完成的 Turn 没有任何下一步。每个选项包含稳定 ID、显示标签、可选说明、强调级别和独立的重复策略，以及以下三类互斥动作：

- **发送消息**：显示标签和实际发送给助手的文本可以不同；点击后创建一个正常的新 Turn。
- **站内跳转**：只接受前端注册的路由名、参数和查询条件，使用 React Router 跳转且不刷新页面；不接受任意 URL。
- **请求操作**：携带 operation ID、候选参数和供用户理解的请求文本，但点击只会形成新的明确用户意图，不由浏览器直接调用业务接口。

各选项互不排斥。站内跳转默认可重复点击，跳转后仍可继续选择发送消息或其他建议；发送消息和请求操作会创建新工作，成功后只禁用自身，防止相同意图或非幂等操作被重复提交，不会连带禁用兄弟选项。执行失败不会消耗该选项。

Agent 还提供独立的 `navigate_to_route` UI 工具。只有用户明确要求“打开 / 前往 / 切换”到目标页面，或立即切换页面确有必要且目标唯一时，模型才应调用它。Agent 只保存注册路由名、参数和查询条件；前端在实时 SSE 收到该 Tool Call 完成事件后校验注册表，并通过 React Router 自动跳转一次。历史 Timeline、重连重放和任意 URL 都不能触发自动跳转；不确定的下一步仍使用可点击选项或 Markdown 链接。

鉴权分为两层。读取选项和发送新 Turn 使用当前浏览器 Session、CSRF 与会话所有权校验；真正的工具操作由 Agent 重新进入 Tool Catalog，Luna API 再按当前用户、项目空间、OAuth Scope、资源归属和最新权限计算结果。Agent 不拥有独立服务账号权限：用户能做的已注册操作才可能成功，用户不能做的操作仍会被业务权限拒绝。只有高风险操作要求参数哈希绑定批准，必要时再要求 Step-up MFA。因此模型生成按钮、用户看见按钮或点击按钮，都不等于已经获得操作权限。

## 会话与恢复

会话保存在 Agent 持有的 `ai` schema 中，不写入浏览器 LocalStorage。重新打开会话时，前端先读取完整 Timeline，再从持久事件游标继续订阅。重复事件会按事件、Item、Part 和 Tool Call ID 去重。

每个可见文本增量会先更新持久 Item，并写入带稳定 `turnIndex` / `timelineIndex` 顺序的 Run Event，再经 Agent SSE 和 Luna API 转发给浏览器。前端不使用每次 Run 都会从 1 开始的事件序号排列跨轮消息，因此流式内容不会先跳到旧消息前方、再被最终 Timeline 修正。刷新、网络抖动或切换页面后，客户端通过 `Last-Event-ID` / `after` 游标补齐缺失片段；终态事件到达后会主动关闭对应会话的订阅，避免无意义重连。

模型服务认证失败、额度不足、限流、超时或暂时不可用时，Agent 只持久化稳定错误码，不向前端透传第三方原始异常。会话时间线会显示对应的本地化失败提示；手动中断也会保留一条明确的终止状态，避免任务无声结束。

Agent 只有在 `LUNA_API_BASE_URL` 与 `AI_AGENT_CALLBACK_SERVICE_TOKEN` 均有效时才向模型注册平台工具，避免模型选择一个当前实例无法执行的工具。本地联调时，Agent 的回调 Token 必须与 Luna API 进程中的同名配置一致。

工具集合还会按当前页面作用域裁剪：平台级页面注册 `getDashboard`、`listProjects`、`createProject` 等平台级能力，只有结构化页面上下文包含有效 `projectId` 时才注册事件、构建、发布、网关和运行时等项目级工具。模型不能通过自行填写其他项目 ID 扩大作用域。

每次创建 Turn 时，Web 会发送版本化的页面上下文信封，包含平台注册路由名、路由模板、页面类型、项目与应用 ID、当前 Tab、受限查询状态、已选资源 ID、可用 Tab、相关站内路由、Locale、时区和客户端时间。Token、回调地址等非白名单查询参数不会进入上下文。Luna API 会覆盖 Locale，并追加服务端请求时间及项目边界是否已经过当前会话授权；这些上下文只帮助模型理解当前工作位置，业务权限仍由每次工具调用重新校验。

Agent 还会把最近 6 轮已选 Run 的用户消息与助手回答按真实 `user` / `assistant` 角色加入 Provider 请求，而不是把所有内容拼成一段普通文本。每条历史消息有独立长度上限，当前问题、页面上下文和工具结果保持更高优先级；历史内容和页面内容始终按不可信数据处理，不能覆盖系统安全规则。

输入区的停止按钮只取消当前会话的活动 Run，不影响其他会话。Agent 会先持久化 `canceled` 终态，再立即中断本实例中的模型流；其他实例通过 PostgreSQL 租约心跳发现取消状态后停止。取消后已展示的部分回答会保留在 Timeline 中，不会把整段会话回滚或打乱。

“新建会话”会优先复用当前项目空间内尚未发送过消息的空会话，不会因重复点击产生一串空记录。每次模型请求都会携带当前会话标题、标题来源和轮次；默认标题的首轮必须调用内建 `rename_conversation` 工具生成简短标题。标题来源为 `assistant` 且当前主要话题明显变化时，模型可以再次调用该工具修正标题。

用户在会话列表中手动改名后，标题来源会持久化为 `user`，列表以锁定图标提示。此时 Agent 不再向模型注册改名工具，数据库更新条件也会拒绝任何 Agent 改名请求；该限制不依赖模型是否遵守提示词，用户标题不会被后续自动命名覆盖。

删除会话成功后会物理级联删除消息、运行、事件、工具调用、批准和检查点，不提供软删除或恢复宽限期。

## 安全边界

- 浏览器只连接 Luna API，不直接连接模型或 `luna-agent`。
- Agent 只能调用 OpenAPI 白名单中的平台 operation。
- 每次工具调用都由 Luna API 重新计算权限。
- Secret、Token、Cookie、Authorization Header 和 kubeconfig 不进入普通会话、SSE 或模型上下文。
- 工具结果和模型输出在发送到浏览器前都会经过统一脱敏。
