# 通知

通知可以把构建、发布、Hook 和访问入口等平台事件发送到协作工具或邮箱。建议先订阅失败事件，避免正常操作产生过多消息。

## 创建渠道

目前支持：

- **Webhook**：适合飞书、Lark、企业微信、钉钉、Slack、Discord、Gotify 和自建告警入口。
- **SMTP**：通过标准 SMTP、STARTTLS 或 TLS 发送邮件。

创建渠道时优先选择内置预设，只需填写目标平台要求的 Token、Key 或地址。使用自定义 Webhook 时，需要填写请求地址、方法、请求头和 JSON 消息模板。

渠道密钥只会写入平台密钥存储，保存后不再回显。Webhook 目标还会经过平台出站安全策略检查，不能用于访问受保护的内网地址。

保存后先点击“测试”，确认目标平台可以收到消息，再创建通知规则。

## 创建规则

规则至少选择一个渠道，并可以按事件类型、严重级别、项目空间、应用和部署配置过滤。目前主要用于失败事件：

- `build.failed`
- `release.failed`
- `hook.failed`
- `gateway.apply_failed`

同一个事件可以发送到多个渠道。投递结果会显示状态、尝试次数和错误摘要，便于排查模板、凭据、网络或目标平台问题。

## 消息模板

内置预设已经提供适合目标平台的消息格式。只有需要自定义内容时才编辑模板。

模板可以使用事件类型、严重级别、资源名称、操作人和详情链接等字段。缺失或无效变量会使投递失败，因此修改后应再次发送测试消息。Secret 仅在发送时注入，不会出现在模板预览和 API 响应中。

如需让通知跳转到平台详情页，请为 API 和 Worker 配置相同的 `PUBLIC_BASE_URL`。未配置时通知仍可发送，但不会包含平台链接。

## SMTP

创建 SMTP 渠道时填写主机、端口、安全模式、账号、发件人和收件人，并在密钥字段中填写密码。保存后留空密码表示继续使用原值。

如果测试失败，请检查端口与安全模式是否匹配、账号是否允许 SMTP 登录，以及网络是否允许连接邮件服务器。

## 验证通知

1. 创建 Webhook 或 SMTP 渠道并发送测试消息。
2. 创建规则，选择失败事件和通知渠道。
3. 在测试环境触发一次失败事件。
4. 在投递记录中确认状态和错误信息。

不要为了验证通知而在生产环境制造故障。

## 常见问题

### Webhook 测试成功，真实事件没有通知

检查规则是否启用、事件类型和过滤条件是否匹配，以及投递记录是否生成。

### 投递持续失败

检查渠道凭据、模板变量、目标地址和对方服务状态。网络错误、限流和服务端错误可能自动重试；配置或模板错误通常需要修正后重新发送。

### 通知里没有详情链接

确认 API 和 Worker 使用相同且可从用户浏览器访问的 `PUBLIC_BASE_URL`。
