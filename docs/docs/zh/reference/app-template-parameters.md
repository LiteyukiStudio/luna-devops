# 应用市场模板参数

本页说明应用市场安装弹窗中模板参数的填写规则、平台自动填入的值，以及参数如何进入运行环境。安装步骤见[应用市场](../use/app-marketplace)。

## 参数类型

安装弹窗按模板定义列出参数，每个参数可能带有以下属性：

| 属性 | 含义 | 留空时 |
| --- | --- | --- |
| 有默认值 | 模板给出了推荐值 | 使用默认值 |
| 自动生成 | 适合密码、密钥、Token | 平台生成 43 个字符的随机值（字符集 `A-Z a-z 0-9 - _`） |
| 必填 | 安装必须有值 | 默认值和自动生成都没有结果时，安装失败 |
| 密钥 | 值只写入密钥存储 | 非必填的密钥参数留空时，不注入对应变量 |

规则：

- 填写的值会去掉首尾空白。
- 密钥参数只以 Secret 形式注入，不写入普通环境变量、安装参数快照或安装结果，安装后也不会回显。
- 多组件模板的所有组件共用同一份参数结果，例如数据库密码只生成一次，同时注入数据库组件和主应用。
- 必填参数缺失时返回 `app_template.value_required`，补全后重新安装；随机值生成失败时返回 `app_template.secret_generation_failed`，安装会中止，不会退回固定值。

## 参数如何进入应用

模板把参数写入组件的环境变量、加密变量、配置文件或密钥文件。安装后这些值成为部署配置中的普通配置，可以在部署配置中查看和修改（加密值不回显）；修改后需要重新发布。

- 模板在连接串中引用密码时会按 URL 规则转义（例如 Neo Blog 的 `DB_URL`、`REDIS_URL`），包含 `@`、`:`、`/` 等字符的密码也能正确连接。
- 修改已经初始化过的数据库密码、密码盐等参数前，先确认应用是否支持；多数数据库只在首次初始化数据卷时读取初始密码。

## 多组件模板的服务地址

多组件模板中，组件之间的服务地址由平台在安装时填入，无需填写：

- 引用其他组件地址的配置会被替换为该组件在项目空间内的服务名，例如 `blog-postgres`。
- 每个依赖额外注入 `<组件>_HOST` 和 `<组件>_PORT` 环境变量，组件键转为大写，例如 `POSTGRES_HOST`、`POSTGRES_PORT`；`_HOST` 的值是集群内完整域名 `<服务名>.<命名空间>.svc.cluster.local`。

这些变量由服务关系提供；需要在部署配置中自定义同名变量时，先调整服务关系，否则发布会因变量名冲突失败。
