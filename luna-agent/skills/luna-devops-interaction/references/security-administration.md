# 安全、管理与账单

## 身份与授权

- 区分认证失败和授权失败。
- Agent 权限等于当前登录用户的实时平台权限；页面上下文不是授权凭证。
- 处理用户、角色、项目成员、Provider 和策略时，提议工具前先明确目标和预期变更。
- 不得从当前页面或会话历史中出现的资源推测管理员身份。
- 用户管理前读取目标账号、平台角色、状态和钱包；创建、角色变更或停用后回读用户，
  并确认当前操作者仍保留必要管理能力。
- OIDC/Git Provider 配置与个人外部身份绑定是不同流程。Provider 保存后执行连接或
  元数据检查；只有实际登录/授权回调成功才说明身份连接可用。
- 选择 Provider、账号或凭据时遵守根 Skill 直接索引的 `resource-resolution.md`。自动采用
  唯一有效资源不代表批准权限变更、密钥轮换或其他高影响操作。
- 注册策略、认证准入和本地密码策略属于站点级安全设置，变更前说明对新用户与现有
  会话的不同影响。

## 密钥与凭据

- 不得要求用户把 Provider Key、Token、密码、私钥或恢复代码粘贴到聊天中。
- 不得泄露已保存的密钥值或包含密钥的工具字段。
- 必须录入或轮换凭据时，引导用户前往平台只写设置。
- 只有平台真实行为如此时，才能说明编辑时留空只写密钥字段会保留原值。
- 创建 Access Token 前先读取可用 scope，按最小权限和实际自动化用途选择；Token
  明文只在平台允许的一次性创建结果中处理，不复制到助手消息或卡片。
- 撤销 Token、OAuth Grant、外部身份或会话后回读状态；发出撤销请求不等于所有远端
  Provider 令牌都已被删除，除非平台结果明确说明。

## MFA、OAuth 与敏感会话

- 区分 MFA 注册、验证、恢复代码、Step-up 和禁用。恢复代码不得进入会话。
- 平台要求 Step-up 时让前端完成绑定 purpose 的验证；不得通过再次询问用户“是否确认”
  或要求验证码文本来绕过流程。
- OAuth 应用管理时明确 redirect URI、grant、scope 和客户端类型；轮换 Client Secret
  会影响现有客户端，应先说明影响并在轮换后验证新的授权流程。
- Web Console、运行命令、数据导出、密钥更新和用户管理按平台策略使用对应 MFA，
  并保留审计结果。

## 高影响管理操作

- 将删除、角色或所有权变更、停用 Provider、轮换密钥、撤销访问权限、缩短保留时间和影响账单的操作视为敏感操作。
- 概括受影响用户或资源及后果，再依赖参数绑定的批准和 MFA。
- 可满足用户意图时，优先选择可逆操作。
- 变更后如有工具，应验证结果状态和审计记录。

## 账单与配额

- 区分当前用量、配置上限、预估成本、实际费用和支付状态。
- 需要实时账单但数据不可用时，不得估算实时金额。
- 变更配额时，明确受影响的资源和周期，以及降低数值是否会中断当前工作。
- 只有读取或明确跳转意图时才提供账单或设置链接；不得用跳转替代可用的配置操作。
- 费用诊断使用同一时间范围核对余额、流水、用量和项目/应用/部署聚合；区分待结算与
  已结算，不用当前余额反推单个资源成本。
- 钱包调整、外部交易补录和费率规则属于高影响平台操作。执行后回读流水、余额与规则
  生效范围，并保留审计标识。

## 平台设置与数据保留

- 站点品牌、语言和普通显示配置与安全、Provider、构建环境、AI、计费配置分开处理。
- 修改外部连接配置后执行对应测试；“配置已保存”不能替代 Provider/SMTP/Registry/
  集群实际可用性验证。
- 数据保留先预览影响范围，再确认清理对象、截止时间和不可逆影响；执行清理后回读
  保留统计或审计记录。
- 系统组件安装属于平台管理员工作流：选择运行集群、填写组件参数、执行安装，并从
  Kubernetes 实时状态验收组件，不以安装记录代替健康状态。

## 验收

- 身份与授权：目标用户、角色、Provider 或策略回读与目标一致，并完成必要审计。
- 凭据：只确认 `secretSet` 或测试结果，不读取或回显明文。
- 账单：流水、余额、用量和规则在同一范围内一致；只读分析不得修改钱包或费率。
- 平台配置：配置回读成功；涉及外部依赖时对应连接测试也成功。
