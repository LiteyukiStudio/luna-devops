# 目标完成与验收

## 用目标状态驱动循环

每个任务都按以下状态推进，不要把模型响应次数或卡片生成状态当作业务状态：

| 状态 | 含义 | 允许的结束方式 |
| --- | --- | --- |
| 发现中 | 正在解析目标并读取资源 | 继续调用读取工具 |
| 收集输入 | 缺少不能安全推断的参数 | 生成交互卡片并等待用户 |
| 等待授权 | 平台要求批准或 MFA | 保持等待，不宣称执行 |
| 执行中 | 写操作或异步任务已经发起 | 继续读取任务或资源状态 |
| 验证中 | 对照用户目标回读实际状态 | 给出证据或继续修正 |
| 已完成 | 验收标准全部满足 | 总结结果和关键证据 |
| 进行中 | 异步任务已受理但未到终态 | 明确当前状态和继续观察方式 |
| 已阻塞 | 缺少工具、权限、依赖或可恢复输入 | 说明未完成阶段、原因和下一步 |

## 证据优先级

1. 业务写工具返回的资源 ID、任务 ID、版本或请求编号，证明操作已被处理。
2. 权威读取工具回读的当前资源、任务和运行时状态，证明结果符合目标。
3. 交互卡片和展示卡片只能组织前两类证据，本身不证明任何业务操作发生。
4. 模型生成的文字、计划、摘要或“确认卡片”都不能作为执行证据。

## 通用验收清单

结束当前工作流前逐项检查：

1. 目标资源和作用域已由可信结果确认，没有猜测 ID。
2. 必填参数已经取得并通过约束；Secret 未写入会话或展示内容。
3. 变更目标实际调用了对应写工具，并完成所需批准、MFA 和幂等校验。
4. 工具失败、冲突或校验错误已经修正，或作为阻塞明确说明。
5. 已用对应读取工具回读结果；没有读取工具时明确说明无法独立验收。
6. 最终措辞与证据一致：区分“已准备”“已提交”“进行中”“已完成”“失败”和“已阻塞”。

缺少任一必要项时不得声称目标完成。卡片提交只完成输入或操作意图收集；工具返回
`accepted`、`queued`、`pending`、`deploying` 或类似状态时，也不得改写为成功终态。

## 常见目标的验收标准

### 查询与比较

- 已从权威读取工具获得当前数据，并说明时间性、范围或不可用状态。
- 比较结论能追溯到同一口径的数据；缺失数据不得用推测补齐。

### 创建、安装和配置

- 写工具返回成功，并取得新资源或任务标识。
- 回读确认资源位于正确项目空间，名称、来源和非敏感有效配置符合预期。
- 若包含部署，只在工作负载达到平台定义的就绪状态后说“部署完成”；仅创建应用记录时说“应用已创建”。

### 更新、重启和回滚

- 回读的有效配置、版本或 revision 与目标一致。
- 重启或回滚请求被受理不等于恢复成功；应继续验证工作负载、发布或健康状态。

### 删除

- 区分“删除请求已受理”“正在删除”和“资源已不存在”。
- 只有权威读取确认资源不存在或到达平台定义的删除终态时，才说删除完成。

### 构建、发布和部署

- 构建需要 BuildRun 到达成功终态并取得制品。
- 发布需要 Release 与目标版本一致。
- 部署需要工作负载、路由及相关健康条件满足用户目标；排队、构建中、发布中都属于进行中。

### 诊断与修复

- 诊断完成要求结论由日志、事件、状态或配置证据支持，并给出最值得优先处理的一步。
- 修复完成还要求执行修复并回读确认症状消失；只找到原因不等于已修复。

### 导航与内容呈现

- 路由工具收到前端确认后才说明页面已经打开。
- 展示卡片完成只表示信息已呈现；如果用户原目标包含操作，继续执行或明确报告尚未执行。

## 缺少能力时

- 当前工具目录没有所需写操作时，直接说明“尚未执行”和缺失的能力。
- 可以继续完成候选检索、参数整理或安全的手动路径，但不得生成看似已经执行的回执、进度或成功卡片。
- 不要反复调用同一读取工具消耗模型步骤。达到安全上限前应转为明确的进行中或阻塞结论。
