# 状态与排障

先判断问题发生在构建、发布、应用运行还是访问入口，再查看对应记录。避免在原因不明时连续重试。

## 先看事件中心

打开侧边栏“事件”。事件列表默认使用“与我相关”，只包含本人事件和本人所在项目空间的事件；平台管理员仅在明确进行全局排障时切换到“全部”。再按项目空间、应用、部署配置、级别和时间缩小范围，这些条件会在当前可见范围内进一步过滤。事件详情会显示失败摘要、关联资源和相关页面入口。

## 构建失败

打开构建记录，检查：

- Dockerfile 路径和构建上下文。
- 依赖是否可以下载。
- 镜像站推送凭据。
- 构建环境的 CPU 和内存。

`exitCode=137` 或 `OOMKilled` 通常表示内存不足，可以提高构建资源后重试。如果尚未配置 Git 和镜像站，可以先部署已有镜像，确认发布和运行链路正常。

如果触发或重试构建时返回 `build.registry_push_credential_required`，本次构建尚未创建。请为该构建使用的目标镜像站新增或绑定一条当前用户或项目空间可见、用途为“推送”或“拉取与推送”的凭据，然后重试；修改分支、Dockerfile 或镜像名称不能解决凭据缺失。

如果返回 `build.image_repository_claimed`，本次构建同样尚未创建：目标镜像仓库已被其它项目空间使用。请修改部署配置的目标镜像仓库，见[镜像仓库路径与 Tag 模板](../reference/image-templates)。

## 发布失败

打开 Release 和部署日志，检查镜像是否存在、集群是否可访问、拉取凭据是否正确，以及端口、环境变量、Secret 和配置文件是否符合应用要求。

应用未就绪或频繁重启时，打开部署目标的**运行时健康详情**抽屉查看结构化诊断：

- **副本异常原因与退出码**：直接查看每个容器的等待或上次崩溃原因（如 `OOMKilled`、`CrashLoopBackOff`、`ImagePullBackOff`、`CreateContainerConfigError`）、退出码（如 `137`）与最后终止时间。
- **探针配置与 Warning 事件**：核对存活/就绪探针路径、端口与最近的 Kubernetes Warning 事件（含发生次数与最后时间）。
- **上次崩溃日志**：在应用“运行日志”工具栏开启**查看上次崩溃实例日志（previous）**，读取容器重启前最后输出的崩溃堆栈；即使容器刚退出重拉，仍可定位根因。

部署有多个副本时，运行日志和 Web Console 每次只连接一个副本。默认“自动选择”会优先选用当前发布中已就绪的副本。要排查某一个副本，例如正在重启或未就绪的那个，请在“副本”下拉框中选中它。下拉框会列出每个副本的就绪状态、重启次数，以及它属于当前发布还是其他发布。所选副本被重建或缩容后不会自动换成其他副本，页面会提示重新选择。使用 CLI 时，可以在 `luna deployment exec` 或 `luna release exec` 后加上 `pod=<Pod 名称>` 来指定副本。

## 访问入口不可用

依次确认域名解析、访问入口状态、Service 端口、可用 Pod 和 TLS 配置。平台管理员还应检查 Gateway、HTTPRoute 和证书状态。

本地域名可以先用 hosts 或 `curl --resolve` 验证，再修改公网 DNS。

## 恢复建议

- 配置错误：修改部署配置并创建新 Release。
- 镜像错误：选择正确镜像后重新发布。
- 应用异常：查看日志，再决定重启或回滚。
- 访问异常：先查访问入口，再查集群网关。

回滚、重启或重新发布都可能影响在线流量。生产环境操作前请确认目标版本、影响范围和恢复方式。
