# 通知

Luna DevOps 将通知分为三类职责边界：

- **个人通知**（账号设置 → 通知）：每位用户维护发往本人账号邮箱和个人 Webhook 机器人的异常与恢复提醒。
- **项目空间通知**（项目空间 → 通知，以及侧栏“集成 → 通知渠道”）：项目空间所有者自助维护所属空间的 Webhook 机器人、自有 SMTP 发信账户、事件订阅规则及跨空间渠道复用。
- **平台全局通知**（系统管理 → 通知）：平台管理员维护全局渠道、高级消息模板和平台级路由规则。

## 配置平台邮件服务

平台管理员先在“站点设置 → 邮件服务”配置一套全局 SMTP。该服务只保存发送连接和发件身份，用于发送注册验证码与个人通知邮件，不对项目空间自定义规则开放代发。

填写主机、端口、安全模式、账号、发件地址和发件名称。使用账号认证时填写密码，密码只写入 Secret Store，保存后不再回显；后续编辑时留空密码表示继续使用原值。

“个人邮件聚合冷却”控制个人异常邮件合并窗口：第一封立即发送，冷却期内同一用户的后续事件合并并在冷却结束后发送摘要（每封最多 20 条，默认 `60` 秒，允许 `0`–`3600`，`0` 表示不等待）。个人通知为每位内部用户独立投递到其账号邮箱，不会把多个用户合并到同一封邮件的 To 或 CC 中。

## 配置我的通知

登录后在“账号设置 → 通知”管理本人通知：

1. 选择是否接收邮件（首次默认启用）。
2. 选择需要订阅的失败与恢复事件。
3. 按需添加个人飞书（交互卡片）、Lark、企业微信、钉钉、Slack 或 Discord 渠道；机器人开启签名校验时可填写可选加签密钥（HMAC-SHA256）。
4. 保存渠道后发送测试消息，并在个人投递记录中查看耗时、响应摘要或手动重新投递。

当前个人订阅支持以下事件：

- 运行时：`runtime.pod_oom_killed`、`runtime.pod_crash_loop`、`runtime.pod_start_failed`、`runtime.workload_degraded`、`runtime.recovered`
- 构建与发布：`build.failed`、`build.webhook_rejected`、`release.failed`、`hook.failed`
- 网关与证书：`gateway.apply_failed`、`certificate.failed`、`certificate.expired`

个人投递仅发送给事件的内部操作者或受影响资源的创建者（同一人只投递一次），并在入队和发送前校验收件人仍具备对应项目空间访问权。每位用户最多保留 10 个个人渠道；渠道测试限制为每用户每分钟 10 次。

## 配置项目空间通知与跨空间复用

**前置条件**：当前账号为目标项目空间的**所有者（Owner）**。项目管理员（Admin）与开发者（Developer）可查看规则、已绑定渠道和投递状态，但不能修改凭据或收件人。

### 1. 创建或复用通知渠道

可在“项目空间 → 通知 → 渠道”或全局侧栏“集成 → 通知渠道”操作：

1. 点击**创建渠道**，选择预设机器人（飞书交互卡片、Lark、企业微信、钉钉、Slack、Discord 等）、自定义 Webhook 或**自有 SMTP 邮件账户**。
2. 选择要绑定的一个或多个所属项目空间。
3. 使用自有 SMTP 账户时，填写团队自管的 SMTP 主机、端口、加密方式（`starttls` / `tls` / `none`）、认证凭据与发件人地址。**默认收件人可留空**，将该渠道作为纯发信账户模板跨多个项目空间和规则复用。
4. 点击对话框底部的**测试连通性**验证无误后保存。

若渠道已绑定多个项目空间，只有同时拥有**全部绑定空间所有者权限**的用户才可编辑或删除该渠道；单一空间的共同所有者可点击**移出当前空间**解除本空间绑定（解绑前需先从本空间规则中移除该渠道）。项目空间與个人渠道均受公网出站安全策略保护，禁止连接云元数据地址、集群内部地址与私网地址。

### 2. 创建项目空间通知规则

在“项目空间 → 通知 → 规则”点击**创建规则**：

1. 填写规则名称，按需限定特定应用或部署目标（留空匹配当前空间全部资源）。
2. 勾选关注的运行时、构建、发布、网关证书或 Hook 事件。
3. 勾选目标渠道（可使用已绑定的项目渠道或平台全局渠道）。勾选自有 SMTP 渠道时，可在规则内单独填写 **To / CC 收件人覆盖**；留空则沿用渠道默认收件人（两者至少一处非空）。
4. 配置告警节流、恢复通知与消息时区：
   - **异常未恢复重发间隔**：范围 `0`–`10080` 分钟，默认 `60` 分钟（首次确认异常立即发送）。
   - **最大重复提醒次数**：范围 `0`–`100` 次，默认 `3` 次；设为 `0` 表示仅首次告警一次。
   - **故障恢复后发送恢复通知**：默认开启；恢复后自动重置告警计数。
   - **消息时间时区**：IANA 时区名称，默认 `Asia/Shanghai`。

## 配置平台全局通知

“系统管理 → 通知”仅对平台管理员开放，用于管理全局渠道、自定义 Go `text/template` 消息模板和跨项目路由规则。每条管理员规则默认要求显式选择项目空间，仅在主动选择“全部项目空间”时才进行全平台广播。

如需在邮件、飞书卡片与消息正文中附带一键直达链接，请为 API 和 Worker 配置相同的浏览器可访问 `PUBLIC_BASE_URL`。

## 排查投递记录

在项目空间、个人设置或系统管理的**投递记录**页面，可按状态、事件类型、渠道或源事件 ID 筛选记录，查看入队时间、完成时间、投递耗时与尝试次数（最多 `6` 次指数退避重试）。点击任意记录可打开诊断抽屉查看脱敏请求快照、远端响应摘要（包括飞书/钉钉应用层错误码）并执行**重新投递**。
