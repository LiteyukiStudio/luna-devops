# 创建部署配置

部署配置描述应用**从哪里来、运行在哪里、如何运行**。一个应用的每个阶段只能有一份部署配置。

在应用“部署”页点击“新增部署配置”，或在部署配置的操作菜单中选择“编辑”，会打开独立的编辑页。页面按“基本信息与来源、运行、发布与触发、高级（Kubernetes）”分区，左侧（窄屏为顶部）导航显示各分区摘要。保存时如有未通过校验的字段，导航会标出出错分区，底部操作栏可直接定位到第一处错误。

## 必填内容

- 阶段：`dev`、`test`、`staging` 或 `prod`，创建后不可修改。
- 目标运行集群。
- 来源：已有镜像或源码仓库。
- 容器端口、每副本 CPU 配额、每副本内存配额和副本数。
- 镜像拉取策略与必要的健康检查。

各字段的允许值、格式和默认值见[字段格式与取值范围](../../reference/field-formats)。

运行集群选项旁的“空闲 / 轻度 / 中度 / 重度 / 满载”徽标是当前集群压力概览，约每 10 秒更新。普通用户只看到等级，不会看到集群精确容量和其他工作负载用量。“不可用”表示平台暂时无法完成观察；压力等级只帮助选择集群，不保证某个 Pod 一定能调度成功。

运行集群选择“平台默认集群”或“当前默认集群”时，部署配置运行在标记为默认的全局运行集群上；没有标记默认集群时，使用最早添加的全局运行集群。项目空间或个人运行集群不会被隐式使用，需要在部署配置中明确选择。部署页展示的集群就是平台实际部署、观察和计量所用的集群；没有可用的运行集群时显示“未配置集群”。

关闭“启用此部署配置”后，部署配置不再参与应用整体运行状态的判定，但不会停止已经运行的 Pod，部署页仍显示其真实副本数。需要停止运行时，将副本数设为 `0`。

## 选择来源

**已有镜像**适合最快上线。填写完整镜像地址，确认目标集群拥有拉取权限，然后保存并创建 Release。

**代码仓库**在“基本信息与来源”中选择：可直接选用应用已绑定的代码仓库，也可点击“绑定代码仓库”就地绑定，绑定成功后自动选中。没有可用的 Git 凭据时，先在“代码仓库 → Git 凭据”中连接账号。然后选择分支和 Dockerfile，再选择拥有推送凭据的镜像站。保存后先执行构建，成功后再发布生成的镜像。

低频选项收在“高级（Kubernetes）”分区，已设置的高级项会自动展开并显示数量，包括工作负载与伸缩行为、容器启动命令与探针、Service、配置文件与密钥文件、部署钩子、安全上下文与调度以及辅助容器。JSON 字段在保存前会校验格式。

开启自动伸缩后，副本数输入会由最小副本、最大副本和 CPU/内存目标利用率取代，至少需要设置一个目标利用率。

副本数可以设为 `0`，以保留部署配置及其 Kubernetes 资源并停止所有 Pod；需要恢复运行时，将副本数改回正整数。在 `0` 与正整数之间切换会直接作用于当前工作负载，无需创建新 Release。启用自动伸缩时，最小副本数必须至少为 `1`，因为当前基于 CPU 和内存 Resource Metrics 的自动伸缩不能从零副本唤醒工作负载。

修改镜像、资源配额、Service、数据卷或高级运行配置后，需要创建新 Release 才会影响当前实例。页面出现“保存并重新部署”时，应在确认影响后使用该操作。

CPU、内存输入是配额，不是直接写入 Kubernetes 的 requests/limits。平台使用所选运行集群的资源分配策略计算实际字段；集群策略中的 `0%` 会省略对应字段。部署配置不能单独覆盖 CPU 或内存 limit。编辑页按所选集群策略显示运行费用的“保底 ~ 上限”估算区间，计费口径见[账单与费用分析](../billing.md)。

部署详情中的运行指标标明“全部副本合计”：CPU、内存用量是全部 Pod、全部容器（含辅助容器）的实时用量之和，分母是同一组容器的 limit 之和，百分比为用量占 limit 的比例；任一容器未设置 limit 时显示 `-`。详情还会显示 request 保底合计和每副本的 request / limit，这些值读取自当前工作负载的 Pod 模板，策略或配额修改在重新部署后才会变化。

## 删除部署配置

删除部署配置会先检查服务关系：只要还有启用的服务关系指向它，删除会被直接拒绝，访问入口和运行资源都不会被清理；先在拓扑中删除或停用这些关系再删除。删除检查与进入“删除中”在同一个事务内完成，删除中的部署配置不能成为新服务关系的目标。

删除最终只会处于“已删除”或“删除失败”。删除失败时，部署列表会显示失败原因（例如仍被服务关系引用、运行资源清理失败或删除任务未能投递）；处理原因后可以再次删除。
