# 项目空间与身份权限工作流

## 适用范围

处理看板摘要、项目空间生命周期、成员角色变更、计费归属转移、个人访问令牌（PAT）、OAuth 应用授权与用户账号设置。

## 标准工作流

1. **解析稳定项目空间 ID**：先读取用户可见项目空间列表，名称匹配存在多个候选时用 `request_choice` 让用户选择；绝不把项目名称、Kubernetes 命名空间或展示标签当作 `projectId`。
2. **区分默认项目与实际权限**：页面上下文中的当前项目仅提供定位线索，不授予权限。项目级读取与变更必须显式传入稳定 `projectId`，由后端 RBAC 实时裁决。
3. **成员与角色治理**：变更成员或角色前先读取当前成员列表与候选用户，明确平台角色与项目角色差异及项目必须保留至少一名 Owner 的约束；成员与计费归属变更属于 `L2` 高风险操作，交由平台逐次参数绑定批准。
4. **凭据与认证安全**：
   - 不索取、不回显、不在正文中传递密码、PAT 明文、OAuth Client Secret、验证码或恢复码。
   - 平台自有系统项目空间不可删除；删除普通项目空间前必须确认其下应用、部署、数据卷与路由影响范围。
5. **验收结论**：创建、更新、置顶或成员变更完成后，以返回结果或权威详情回读确认最新状态，区分已生效事实与待对方确认的转移请求。
