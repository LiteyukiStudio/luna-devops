# 配置与连接

本页介绍站点设置，以及平台连接 Git、镜像站和运行集群时需要准备的内容。

## 站点与账号

平台管理员可以配置站点标题、Logo、登录页说明、默认语言、主题和界面风格。用户可以在个人设置中覆盖主题、明暗模式和界面风格；个人设置优先于站点默认。

全局设置会把当前页签的保存操作显示在页签操作区。修改内容后保存按钮才会启用；切换页签不会自动保存配置。

“注册与邮件”可以分别控制邮箱注册和 OIDC 注册。邮箱注册需要配置 SMTP；密码保存后不会回显，修改其他设置时留空即可保留原值。

## 安全策略

生产环境会启用基础浏览器安全防护。HSTS 只应在确认站点始终通过 HTTPS 访问后启用，否则浏览器可能无法继续通过 HTTP 访问该域名。

平台可以要求敏感操作完成 MFA 二次验证。启用全局策略前，至少应确保一名可用的平台管理员已经绑定离线 TOTP 验证器，避免所有管理员都无法执行敏感操作。

## Git Provider

Git Provider 用于连接 GitHub、Gitea 或 GitLab，并为仓库搜索、Webhook 和构建提供授权。

1. 创建 Provider，填写服务地址和类型。
2. 配置 OAuth 或访问凭据。
3. 测试连接后，再在项目空间或应用中绑定仓库。

凭据可以限制为个人、指定项目空间或全局使用。删除 Provider 会同时删除属于它的凭据；执行前请确认仓库绑定和构建链路不再依赖它。

如果只想先验证运行链路，可以跳过 Git Provider，直接部署已有镜像。

## 镜像站

镜像站用于保存构建产物，并向运行集群提供镜像。平台支持 Harbor、Gitea Registry、DockerHub 和通用 OCI Registry。

创建凭据时需要选择拉取、推送或两者兼具，并限制允许使用的用户或项目空间。删除镜像站会同时删除其凭据，请先确认构建和发布不再依赖它。

自动构建需要推送权限；部署已有镜像时，应重点确认运行集群拥有拉取权限。部分 Registry 会关闭仓库或标签列表接口，此时搜索可能不可用，但仍可手动填写完整镜像地址。

构建变量可以在全局、项目空间、应用和部署配置四个层级设置，越靠近部署配置的同名值优先。Build Args 和普通变量会进入构建记录，不适合保存密钥；敏感值应使用密钥变量。

## 运行集群

运行集群是 Release 的发布目标。添加集群时，请提供平台服务可以访问的 kubeconfig，并先测试连接。

如果 API 或 Worker 运行在容器中，kubeconfig 不能使用仅宿主机可访问的 `127.0.0.1`。建议先执行 `kubectl config view --raw --minify --flatten`，再保存输出。平台仅接受 HTTPS API Server 和内联认证材料，不支持需要执行本机命令或读取本机文件的认证方式。

集群设置还包括访问域名后缀、外部访问协议、Gateway 和 TLS。选择 TLS 模式时：

- 上游代理或 CDN 已终止 HTTPS：选择“上游代理已终止 TLS”。
- 集群 Gateway 使用已有证书：选择“Gateway 终止 TLS”并配置 TLS Secret。
- 使用 cert-manager：配置已有 Issuer 或 ClusterIssuer，并确认验证方式在集群中可用。

平台不会替你创建 ACME 账号或 DNS Provider 凭据。修改 Gateway、证书或集群连接前，请确认影响范围和恢复方式。

项目空间、应用和部署阶段的标识创建后不能修改。删除失败或保留数据时，原标识和 PVC 可能仍被占用；新资源不会自动接管旧数据。

## 个人令牌与密钥

个人令牌用于脚本、CI 或外部自动化。令牌明文只在创建后展示一次，请按最小权限创建并安全保存；撤销后会立即失效。

Secret、Token 和镜像凭据不会明文回显。编辑时留空表示保留已有值，只有需要替换时才输入新值。
