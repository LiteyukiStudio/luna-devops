# 运行观察与计费口径

## 业务不变量

- `DeploymentTarget.Replicas` 是 configuredReplicas，只表达用户配置和基准预估。
- Kubernetes workload `Spec.Replicas` 是 desiredReplicas；`updatedReplicas`、`readyReplicas` 和 `availableReplicas` 分别用于发布进度、就绪度和可用性。
- 实时指标的容量分母必须来自同一次 Kubernetes 观察中的 desiredReplicas。上游不可达时返回 `unavailable`，不能用数据库配置或上一次响应伪装当前状态。
- 运行账单只使用 `runtime_observations` 中对应部署目标和已完成小时的观察。观察快照记录副本数、CPU/内存配置、工作负载创建时间和观察时间，并通过 `(deployment_target_id, period_start)` 幂等。

## 观察与结算

Worker 在当前小时内持续 upsert 当前窗口观察；窗口关闭后不再修改。结算最近完整小时期间，只读取对应窗口的快照：

1. 找到有效快照后，按该窗口的 desiredReplicas、CPU request 和 memory request 计算 replica-hours。
2. desiredReplicas 为 `0` 是合法零用量窗口，仍保留结算记录的幂等语义。
3. 快照缺失、Kubernetes 观察失败或配置缺少权威快照时，窗口保持待补状态并跳过结算；禁止拿结算时的实时值回填。
4. 账单记录仍按目标、计量项和窗口幂等。重复任务不会重复扣费。

当前实现按小时保存一个窗口观察，能够防止把最新值套用到更早窗口；若产品需要精确表示同一小时内的多次 HPA 扩缩容，应在独立事项中把快照扩展为带 `segmentStart/segmentEnd` 的不可变采样段，并在此基础上重算未结算窗口。
