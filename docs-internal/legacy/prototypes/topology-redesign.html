设计依据

为什么这样改

1分层 DAG 替代环形布局

微服务拓扑的事实标准是分层有向图（Backstage、Kiali、AWS X-Ray 均采用），布局算法对应 Sugiyama 层次图框架。调用方向自上而下、层级即依赖深度，「主调在上、被调在下」成为布局语义本身，不再需要逐条追箭头。实现上可将 ECharts layout: 'circular' 改为自定义 layered 坐标（按最长路径分层 + 重心法排序减交叉）。

2格式塔分组：泳道与留白

按服务分层用泳道（共同区域原则）与 8pt 网格留白（接近性原则）组织节点，同层服务在视觉上自然成组；接入 / 核心 / 支撑 / 基础设施四类用色盲安全的定性色板（Okabe-Ito）区分（相似性原则），色相只承担分类，不承担状态。

3语义双重编码（WCAG 1.4.1）

状态不用颜色作为唯一通道：色点 + 文字徽章 + 图标三重复合，与项目 StatusBadge 五档 tone（success / warning / danger / info / neutral）一一对应。异常状态提高视觉权重，正常状态弱化（对比度层级服务于一目了然的异常发现）。

4先总览，细节按需

遵循 Shneiderman 信息检索口诀「Overview first, zoom and filter, then details-on-demand」：画布只保留名称 / 状态 / 出入度 / 协议；点击节点触发焦点邻域高亮（degree-of-interest 淡出非关联元素），协议、环境变量注入、健康检查项等放进详情侧滑，避免画布信息过载。

5连线的可读性工程

边使用平滑贝塞尔曲线沿层间通道走线（连续性原则），实线 / 虚线区分服务绑定与手动声明（样式即语义），线宽统一、异常状态才上色；所有视觉通道在底部图例中给出可解码说明，箭头恒定指向被调方。

6降级与响应式策略

窄屏下泳道标签折叠为行内标题，节点卡片纵向堆叠，连线层自动隐藏并复用现有移动端关系列表（MobileRelationItem）——图与列表是同一数据的两种投影，各自适配自己的视口。
