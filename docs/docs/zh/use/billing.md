# 账单与费用分析

账单页用于查看账户余额、消费趋势，以及费用具体产生在哪些项目空间、应用和部署配置中。

项目空间产生的费用由其“计费归属账户”承担。归属人变更后，新费用由新的归属人承担，历史账单不会迁移。接受费用归属转移前，请确认项目空间和发起人无误。

普通用户只能查看自己的账单。平台管理员可以查看全部用户或指定用户的账单。页面支持按时间、用户和项目空间筛选，账单流水用于审计，费用分析更适合定位主要开销。

管理员选择“全部用户”时，余额卡片显示“平台钱包合计”，即所有用户钱包余额之和；它不是某个账户的余额，因此不显示余额状态或余额不足提醒。选择具体用户后才显示该账户的余额状态。

## 时间范围口径

- 费用按**用量发生时间**归入时间范围：每条用量以其计量周期的开始时间为准，整条计入开始时间所在的范围，不按结算时间、也不按周期重叠拆分。例如 23:00–24:00 的运行用量在次日 00:05 结算，仍计入前一天。
- 手工充值、调账等没有用量记录的流水以记账时间为准。
- “今日”“本月”按浏览器所在时区的自然日和自然月计算；所选时间范围的起止日期同样按本地时区解释。
- 账单流水与用量记录的“发生时间”列展示上述用于筛选的时间，并按它排序。

账单流水会同时展示标准原因和创建流水时记录的具体说明；说明为空或与标准原因相同时不会重复显示。

平台以 Credits 结算。管理员可以配置现实货币单位和展示换算比例，但这不会改变底层结算单位，也不会重算历史账单。

## 价格表

账单页的“价格表”会列出平台资源计费项，包括构建 CPU 与内存、运行资源、持久化存储和访问流量。AI Token 价格按模型维护在“全局设置 → AI 助手”的模型目录中，不在通用价格表中调整。配置方法见安装区的[设置价格](/start/pricing)。

停用的资源计费项仍会保留在价格表中，但当前不会产生费用。管理员修改资源价格或启停状态后，只影响后续产生的用量，已经结算的账单不会重算。

## 数据卷费用

平台托管数据卷在可用、已预留或使用中时持续产生存储用量。平台优先按 Kubernetes 实时回读的 PVC 容量计量；集群暂时不可达时才使用已记录的请求容量。外部引用卷不产生托管存储费用。

导入和导出的实际传输字节使用 `storage.transfer_gib` 计量。每个成功、失败、取消或过期的 Transfer 任务最多结算一次；重试会创建新的 Transfer，并按该次实际传输量独立结算。该计量项默认停用且单价为 `0`，管理员可以在“全局设置 → 计费配置”的价格表中启用并设置单价。

## 费用分析

费用分析按项目空间、应用和部署配置汇总已结算用量，并区分构建、运行、存储、访问和其他费用。

数据卷存储和导入导出传输属于项目空间，不归属任何部署配置，在费用分析中统一显示为“项目存储”一行。其他无法关联到具体应用或部署配置的用量会显示为“未关联”。如果费用异常，请缩小时间范围并逐层查看项目空间、应用和部署配置。

运行资源通过 Kubernetes `metrics.k8s.io` 按自然分钟观察，但账单仍按已完成的自然小时各写一条 CPU 和内存流水。每个分钟区间分别按 `max(有效 request × 期望副本数, 实际用量)` 计费，再乘以该区间的有效时长并汇总为 vCPU·小时和 GiB·小时；工作负载在分钟中途创建时会裁剪时长，重叠区间不会重复计算。

有效 request 是观察时从工作负载 Pod 模板读取的每副本实际 requests，按全部容器（应用容器和辅助容器）求和；实际用量同样是该工作负载全部 Pod、全部容器之和，不含部署 Hook 任务的 Pod。因此修改运行集群的资源分配策略或部署配置的配额后，要等重新部署生效才会改变计费保底。

当 `metrics.k8s.io` 不可用但 Kubernetes 已确认工作负载运行时，该分钟只按有效 request 保底；Pod 模板没有对应 request（例如策略为 `0%`）时不会凭空估算该维度。完全缺失的分钟不插值、不外推，期望副本为 0 的分钟不产生运行用量。账单 metadata 中的覆盖率表示本小时存在有效运行观察的时长占完整小时的比例；历史观察保留当时的有效 request 和渲染该工作负载时使用的集群策略，已结算账单不会因后续策略修改而重算。

部署配置编辑页显示的运行费用估算是区间：保底按所选运行集群策略的 request 百分比 × 配额 × 副本数，上限按 limit 百分比 × 配额 × 副本数；启用自动伸缩时，保底使用最小副本数、上限使用最大副本数。策略某项 limit 为 `0%`（不设置 limit）时没有费用上限。估算不含辅助容器自身的资源。

## AI Token

AI 助手只按 Provider 官方 `usage` 中经校验的 Prompt、Completion、缓存 Prompt 和 cache-write Prompt 用量计费，费用归属发起对话的用户账户。Completion 已包含 reasoning 用量，不会重复扣费。价格使用每百万 Token 的 Credits，并在 Run 创建时保存三项价格快照；后续修改模型目录只影响新 Run。Provider 未返回或返回非法 `usage` 时，该次调用进入对账而不是用 `0` 或预授信值结算。

## 访问流量

访问费用按平台访问入口产生的响应出站流量计算，不包含集群内服务互访流量。

访问流量采集是可选能力。平台管理员需要从应用市场为目标运行集群安装 `Luna Gateway Traffic Probe`。探针的上报机制、鉴权方式、配置项与排障步骤见[网关流量探针](../reference/gateway-traffic-probe.md)。

账单页可能显示：

- **未部署**：目标集群尚未安装采集组件。
- **等待上报**：组件已就绪，但尚未收到有效流量数据。
- **不可用**：平台当前无法读取目标集群状态。

已经结算的用量会作为账单历史保留。
