# 创建部署配置

部署配置描述应用**从哪里来、运行在哪里、如何运行**。一个应用的每个阶段只能有一份部署配置。

在应用“部署”页点击“新增部署配置”，或在部署配置的操作菜单中选择“编辑”，会打开独立的编辑页。页面按“基本信息、来源与构建、运行配置、发布与触发、钩子、安全与调度”分区，左侧（窄屏为顶部）导航显示各分区摘要。保存时如有未通过校验的字段，导航会标出出错分区，底部操作栏可直接定位到第一处错误。

## 必填内容

- 阶段：`dev`、`test`、`staging` 或 `prod`，创建后不可修改。
- 目标运行集群。
- 来源：已有镜像或源码仓库。
- 容器端口、每副本 CPU 配额、每副本内存配额和副本数。
- 镜像拉取策略与必要的健康检查。

运行集群选项旁的“空闲 / 轻度 / 中度 / 重度 / 满载”徽标是当前集群压力概览，约每 10 秒更新。普通用户只看到等级，不会看到集群精确容量和其他工作负载用量。“不可用”表示平台暂时无法完成观察；压力等级只帮助选择集群，不保证某个 Pod 一定能调度成功。

## 选择来源

**已有镜像**适合最快上线。填写完整镜像地址，确认目标集群拥有拉取权限，然后保存并创建 Release。

**源码仓库**需要先绑定仓库、选择分支和 Dockerfile，再选择拥有推送凭据的镜像站。保存后先执行构建，成功后再发布生成的镜像。

低频选项收在各分区的高级选项中，已设置的高级项会自动展开并显示数量：启动命令、拉取策略、生命周期和探针位于“运行配置 → 容器启动与健康检查”；StatefulSet 位于“运行配置 → 存储”；调度规则、安全上下文和辅助容器位于“安全与调度”；部署 Hook 位于“钩子”。JSON 字段在保存前会校验格式。

开启自动伸缩后，副本数输入会由最小副本、最大副本和 CPU/内存目标利用率取代，至少需要设置一个目标利用率。

副本数可以设为 `0`，以保留部署配置及其 Kubernetes 资源并停止所有 Pod；需要恢复运行时，将副本数改回正整数。在 `0` 与正整数之间切换会直接作用于当前工作负载，无需创建新 Release。启用自动伸缩时，最小副本数必须至少为 `1`，因为当前基于 CPU 和内存 Resource Metrics 的自动伸缩不能从零副本唤醒工作负载。

修改镜像、资源配额、Service、数据卷或高级运行配置后，需要创建新 Release 才会影响当前实例。页面出现“保存并重新部署”时，应在确认影响后使用该操作。

CPU、内存输入是配额，不是直接写入 Kubernetes 的 requests/limits。平台使用所选运行集群的资源分配策略计算实际字段；集群策略中的 `0%` 会省略对应字段。部署配置不能单独覆盖 CPU 或内存 limit。
