# 跨领域诊断与平台治理工作流

## 适用范围

处理“为什么访问不通 / 发布失败 / 构建报错 / 扣费异常 / 没收到通知”等跨领域排障，以及平台事件检索、账单与用量明细、通知渠道/模板/规则/投递重试、全局系统配置与 AI 可观测运营查询。

## 标准工作流

1. **先聚合概览、再精准下钻（禁止碎片化盲查）**：
   - 项目级排障先调用项目诊断聚合工具（`getProjectDiagnostics`），一次获取应用/发布统计、近期失败或进行中的构建与发布、以及异常访问入口列表。
   - 定位到具体异常部署目标后，调用部署目标诊断聚合工具（`getDeploymentTargetDiagnostics`），一次获取工作负载副本实时观察、最近发布记录、Pod 重启/等待原因、Warning 事件与绑定路由状态。
   - 找到交付链上**第一个异常边界**（代码源 → 构建 → 镜像 → 发布 → 运行副本 → 网关路由）后，仅对该异常节点补充读取对应构建日志、发布日志或容器运行日志。
2. **事实、推断与建议分离**：
   - 关联同一时间窗口内的资源状态、`failureCode`、`observationCode`、平台事件与 `requestId`。
   - 严格区分“已观测事实”“合理根因推断”与“待确认假设”；只定位根因不等于已修复，给出最小可回滚修复动作，待用户确认并通过平台审批后再执行，修复后沿原故障路径复验。
3. **账单、通知与系统治理边界**：
   - AI 模型调用费用只归属发起用户个人钱包；构建、运行时、存储和网关流量费用可归属项目空间，查询账单时注意区分个人范围与项目范围。
   - 排查通知未送达时依次核对通知偏好、渠道绑定、规则事件过滤条件与投递记录错误详情。
   - 全局配置、AI 模型目录、用户管理与数据保留清理仅限具备对应平台权限的管理员执行，权限不足时直接如实说明。
