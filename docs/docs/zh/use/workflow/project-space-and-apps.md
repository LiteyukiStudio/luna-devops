# 项目空间与应用

## 看板和项目空间的可见范围

看板固定使用“与我相关”，只汇总当前账号作为成员的项目空间及其关联资源，不提供全局范围切换。项目空间列表同样默认使用“与我相关”；平台管理员只有在全局盘点、跨项目排障或明确查找其他项目空间时，才在项目空间列表切换到“全部”。“全部”不会绕过后端权限校验。

看板和项目空间概览中的应用数不包含正在删除或已删除的应用。看板“最近应用”的最近活动是每个应用各自最近一次事件，项目空间快捷入口的最近活动是该项目空间自己的最近一次事件。项目空间概览的失败发布数只统计最近 7 天内失败的发布。

项目空间概览的“访问入口”显示“就绪数/启用数”，每次打开时由网关实时观察，停用或正在删除的访问入口不计入。只要有访问入口无法观察，该指标显示“网关实时状态暂不可用”，而不是 0 个就绪；确认运行集群和网关可达后刷新页面即可。

## 创建项目空间

项目空间是团队和资源的**逻辑隔离边界**。通常按产品、团队或客户划分；同一空间内共享成员、应用、构建、发布、数据卷和访问入口。

创建时填写名称和稳定标识，然后按最小权限添加成员。标识创建后不能修改。

进入项目空间后默认显示“概览”。侧栏依次为“概览”“应用”“共享配置”“数据卷”“成员”和“服务关系”；多个应用共用的构建变量、运行配置和钩子都在“共享配置”中按页签维护。

## 选择成员角色

项目空间角色与访问凭证的 Scope 会同时生效；只有两者都允许时，操作才会放行。平台管理员位于项目成员角色矩阵之外，可以执行平台级管理，但仍需满足当前访问凭证的 Scope。

- **所有者**：管理项目空间和成员，并可执行项目空间删除等所有项目操作。
- **管理员**：管理成员和大多数项目资源，可删除应用、部署配置和访问入口，但不能删除项目空间。
- **开发者**：创建、更新、发布和重启工作负载；不能删除应用、部署配置、访问入口或项目数据卷。
- **查看者**：只读查看项目资源和运行状态。

在普通项目成员中，删除项目空间仅允许所有者执行；删除应用、部署配置、访问入口和项目数据卷仅允许所有者或管理员执行。删除前仍会执行资源引用、数据影响和进行中任务等业务校验。

构建日志、部署实时指标、AI 任务进度和数据卷传输会在连接期间持续复核账号、凭证 Scope 与项目角色。账号被禁用、会话或 Token 被撤销、成员被移除，或权限服务暂时不可用时，现有流会停止；恢复权限后需要重新发起请求。

## 创建应用

应用表示一个可以独立部署的服务，例如 Web、API 或 Worker。一个代码仓库可以对应多个应用，一个应用也可以拥有开发、测试、预发和生产等不同部署阶段。

1. 进入项目空间的“应用”。
2. 创建应用并填写名称、标识和说明。
3. 进入应用的“部署”页继续创建部署配置。

应用本身只负责组织服务；代码仓库、镜像、端口、资源、环境变量和数据卷都在部署配置中设置。应用详情按交付顺序分为“概览”“构建”“部署”“访问入口”“拓扑”和“设置”；“设置”只用于修改应用基本信息，以及查看、维护或解绑已绑定的代码仓库。

> 删除应用会停止新的交付操作并异步清理平台托管的运行资源。项目数据卷默认保留，避免误删持久数据。

如果其他应用仍通过服务关系引用该应用，删除会被直接拒绝，运行资源不会被清理；先在拓扑中删除或停用这些服务关系再删除。同一应用内部不同部署配置之间的服务关系不影响删除。删除中的应用不能成为新服务关系的目标。

删除最终只会处于“已删除”或“删除失败”。删除失败时，应用列表会显示失败原因（例如仍被服务关系引用、运行资源清理失败或删除任务未能投递）；处理原因后可以再次删除。

## 设置网络隔离

每个项目空间默认只允许项目空间内的应用互相访问、网关访问应用，并允许应用访问公网；其他项目空间、私网、保留地址、集群节点和 Kubernetes API 始终无法访问。需要更严格的隔离时，项目空间管理员可以在“拓扑 → 网络隔离”中收紧，保存后平台会立即重新下发网络策略。

| 设置 | 可选值 | 效果 |
| --- | --- | --- |
| 入站 | 项目内互通（默认） | 项目空间内的应用可以互相访问 |
|  | 按服务引用放行 | 每个部署配置只接受自己的副本，以及在拓扑中通过服务引用指向它的部署配置；没有服务引用的应用之间无法互相访问 |
| 出站 | 允许公网（默认） | 可以访问公网，以及其他应用的访问入口 |
|  | 仅白名单 | 只能访问出站白名单中的地址和访问入口 |
|  | 禁止外联 | 只能访问项目空间内的应用和集群 DNS |

出站白名单每行一条 `CIDR 端口,端口`，最多 64 条，例如 `1.1.1.1/32 443`。写了端口时只放行 TCP；省略端口表示全部端口和协议，需要放行 UDP（如外部 DNS、NTP）时不要写端口。私网和保留网段始终拒绝，不能写进白名单；需要访问内网服务时联系平台管理员。

切换为“按服务引用放行”前，先确认应用之间的调用都已在拓扑中建立服务引用，否则未声明的调用会立即失败。

### 内部服务

数据库、队列、后台 Worker 等不需要对外提供访问的部署配置，可以在部署配置“高级 → 服务”中开启“内部服务”。开启后网关流量无法到达它的 Pod，也不能为它创建访问入口；已有访问入口时需要先删除。该隔离要求网关控制器运行在 Pod 网络中；网关使用 hostNetwork 时，网关流量以节点地址到达，内部服务无法与之区分。
