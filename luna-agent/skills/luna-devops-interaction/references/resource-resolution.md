# 资源候选解析与默认选择

## 适用范围

在项目空间、应用、部署配置、运行集群、镜像站、Git Provider、Git 账号、代码仓库、
凭据、应用模板、网关、域名后缀、配置集、变量集、通知渠道等平台资源之间建立引用前，
统一执行本规则。它只决定“使用哪个已有资源”，不代替创建参数、风险批准、MFA、写操作
或结果验收。

## 先建立有效候选集

1. 使用对应读取工具获取当前用户在当前作用域内可见的实时资源。
2. 根据当前任务过滤无权限、已禁用、未就绪、类型不匹配、作用域错误、版本不兼容、
   容量不足或缺少必要连通性的资源。
3. 用户已经明确给出资源名称或 ID，或当前页面唯一指向一个可信目标时，先验证该目标，
   不再把同类资源全部交给用户重选。
4. 候选的名称用于说明，真实 ID 用于后续工具参数；名称相同不能证明是同一资源。

不得把列表接口返回的第一项直接当默认值。只有过滤后剩下的候选才参与数量判断。

## 按候选数量继续

| 有效候选 | 处理方式 |
| --- | --- |
| 0 个 | 说明缺失或不可用原因；仅在工作流确实需要且存在创建工具时，收集创建参数或提出创建 |
| 1 个 | 自动采用并继续，不生成选择卡片、不发送确认问题，也不在表单中保留只有一个选项的必填选择字段 |
| 2～5 个 | 当前任务无法从用户意图或可信上下文确定目标时，使用可直接选择的交互卡片 |
| 6～50 个 | 使用带搜索语义的 `select` 字段，label 为名称、value 为真实 ID，并设置 `submissionFormat: label_value` |
| 超过 50 个 | 先按用户目标缩小范围或调用分页搜索，不把截断列表伪装成完整候选集 |

自动采用唯一候选后，可以在自然语言或变更审阅中简短说明“将使用 X”，但不得停下来等待
确认。后续表单只收集仍然存在真实选择或缺失的字段。

## 在候选选择中提供新建入口

当用交互卡片让用户从已有资源中选择（项目空间、应用、集群、镜像站、Git 账号、凭据、
仓库、模板、网关、域名、配置集、变量集、通知渠道等）时，只要该平台支持创建对应资源，
就必须在候选之外额外提供一个“新建”入口，不得只给出现有候选让用户被迫二选一：

- `candidate_picker` / `candidate_select` 使用其 `creationAction` 生成次级“新建”按钮；
  通用卡片使用 `groupActions` 增加一个 `send_message` 动作。
- 新建入口的 label 明确指出资源类型，例如“新建项目空间”“新建集群”“绑定新的 Git 账号”。
- 新建入口的 `send_message` 应把用户带入该资源的创建流程：说明缺失，并收集创建所需参数；
  创建完成并通过回读取得真实 ID 后，自动回到原工作流继续，不要让用户重新开始。
- 仅在平台确实没有对应创建能力时才省略新建入口，并说明只能使用现有候选。
- 新建入口与候选选择互斥：用户选择新建即放弃当前候选；两者都是可独立选择的动作。
- 高风险或平台不允许普通用户创建的资源（如受管集群、平台级配置）不生成新建入口，
  按 0 个有效候选的阻塞流程说明原因。

## 覆盖与例外

- 用户明确要求“换一个”“不要使用当前资源”“新建”“查看其他候选”时，停止自动采用，
  重新发现替代资源；没有替代项时提供创建流程或解释阻塞。
- 唯一候选不满足健康、权限、兼容性、容量、隔离或安全要求时，按 0 个有效候选处理，
  不得为了减少提问而勉强使用。
- 自动选择资源不等于批准高风险操作。删除、覆盖、权限变更、公开暴露、费用变化等仍由
  平台批准和 MFA 机制门控。
- 来源类型、架构方案、数据保留、依赖复用等具有实质权衡的决策不是“已有资源候选”；
  即使某一分支当前只有一个资源，也不能因此替用户决定整个方案。
- 平台或项目明确配置的默认资源只有在实时验证通过且符合当前任务时才优先；“默认”标签
  不能绕过有效候选过滤。

## 写入前保持一致

长流程中，候选可能在用户填写其他参数时发生变化。执行写操作前重新验证自动采用资源仍然
存在、可用且处于相同作用域。若唯一候选消失或新增候选，不要无故推翻用户已经明确选择的
目标；只有原目标失效或用户要求更换时才重新进入解析流程。

## 常见场景

- 只有一个可用运行集群：直接用于部署配置，表单不再询问集群；集群不可用时改为创建、
  修复或选择其他集群流程。
- 只有一个可用镜像站：源码构建输出和镜像发布默认使用它；仍需验证推送权限和目标集群
  拉取能力。
- 当前用户只有一个可写项目空间：直接作为目标项目空间；用户要求新建或指定另一个空间时
  再进入创建或搜索流程。
- 只有一个与仓库匹配的 Git 账号或凭据：验证其确实能读取目标仓库后直接采用；认证失败
  不能当作有效唯一候选。
- 只有一个兼容应用模板、网关、通知渠道或配置集：当前意图已经明确该资源类型时直接采用；
  如果用户正在比较方案，则仍应展示事实而不是自动执行写操作。
