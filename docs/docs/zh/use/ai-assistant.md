# AI 助手

AI 助手可以结合当前页面和你的权限，查询资源、解释状态、分析日志，并协助完成部署和日常运维。

## 可以做什么

- 查找项目空间、应用、构建、Release、集群和访问入口。
- 分析失败状态并给出可验证的排查步骤。
- 根据仓库、现有镜像或应用市场模板准备部署。
- 通过表单收集参数，在确认后执行平台操作。

直接描述目标即可，例如“检查这个应用为什么无法访问”或“用这个仓库部署 API”。不熟悉容器或 Kubernetes 时，可以说明“第一次部署”，助手会按步骤解释必要概念。

## 能力边界

> AI 助手是操作入口和诊断助手，不是权限绕过工具，也不能替代上线前的人工验收。

- 助手只能访问你本来有权访问的资源。
- 删除、发布、权限变更等高风险操作会展示目标和参数并等待确认；参数变化后需要重新确认。
- 构建、发布等异步操作只有在权威状态进入终态后才算完成。
- 外部服务不可用、权限不足或平台缺少能力时，助手会说明未完成步骤，不会把受理请求报告为成功。
- AI 可能理解错误。执行变更前应核对资源、环境、镜像版本和影响范围。

## 信息安全

- 页面上下文不会包含密码、Token 或 Secret 明文。
- 密钥通过受控表单和工具直接交给平台，不写入普通聊天消息；保存后不回显。
- 读取公开网页时不会携带浏览器 Cookie、登录 Session、Token 或 Git 凭据。私有仓库应先连接 Git Provider。
- 不要在对话中粘贴私钥、生产数据库密码、完整 kubeconfig 或其他长期凭据。
- 工具详情和诊断结果可能包含资源名、日志和配置片段，应按内部运维数据管理。

## 开始使用

平台管理员需要先在“全局设置 → AI 助手”配置兼容 OpenAI `chat/completions` 的 Provider、可用模型、访问范围和个人钱包计费。启用后，页面右下角会出现入口。

如果入口不存在，请联系管理员确认功能和账号范围；如果模型暂时不可用，保留当前会话并稍后重试。
