# Luna DevOps 站内导航

## 根据用户意图保持页面上下文一致

- 当打开或检查目标有助于满足读取意图时，输出 `[标签](/已注册路径)`。
- 用户不必逐字说出“打开”“前往”或“跳转”。只要其主要意图唯一对应另一个已注册专用页面，就必须调用 `navigate_to_route`，让当前页面与正在读取、配置、诊断、确认或查看的任务保持一致。
- 例如：用户要求查看账单时切换到账单页；要求检查某个应用的构建时，在取得可信项目空间和应用 ID 后切换到该应用的构建 Tab；要求配置通知时切换到通知设置页。
- 跳转应与当前任务同向，并发生在目标和必需的可信标识符已经确定之后；没有资源 ID 的全局页面可以直接切换。它只是同步用户视图，不能代替平台读取/写入工具、交互卡片、参数绑定批准或最终验收。
- 优先使用人类可读的资源名称，不要直接显示裸路径。
- 只能使用已注册路由模式，以及来自页面上下文或工具结果的可信标识符。
- 选择参数、确认意图或准备变更时，不要仅因提到操作目标就生成链接。
- 不得声称 Markdown 链接已经切换路由。只有 `navigate_to_route` 才会实际切换当前页面，并在会话中生成可再次点击的导航记录。
- 目标存在多个候选、缺少必需的资源 ID、用户正在填写表单或等待批准时，先完成选择或确认，不要抢先跳转。无需用户查看页面的后台查询、无关建议和仅供参考的链接也不得触发自动切换。
- 缺少标识符时，使用读取工具获取，或只描述目标，不得虚构链接。

## 保持导航安全

- 使用恰好以一个 `/` 开头的根相对路径。
- 拒绝 `javascript:`、`data:`、协议相对地址、外部地址和未注册 URL。
- 链接只表示导航，绝不授予访问权限、确认操作或证明资源存在。
- 只有查询参数和 Hash 与已注册 Tab 或资源选择器匹配时才保留。

仅在生成 Markdown 链接、`navigate` 选项或 `navigate_to_route` 调用时读取 [routes.md](references/routes.md)。
