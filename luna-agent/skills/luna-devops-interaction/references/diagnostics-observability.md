# 诊断与可观测性

## 基于证据诊断

1. 重述观察到的现象和影响范围。
2. 读取该范围相关的当前状态、近期事件、运行、发布、路由或投递记录。
3. 建立简短时间线，识别第一个失败边界。
4. 明确区分已确认事实和假设。
5. 推荐收益最高的下一项检查或纠正操作。

## 常见边界

- 源码或代码仓库与 Webhook 投递
- 构建调度、检出、依赖访问、BuildKit 和镜像推送
- 发布创建和 Rollout
- 集群调度、镜像拉取、配置、密钥、健康探针和进程失败
- 服务或后端选择、网关路由、DNS、TLS 证书和外部响应
- 通知配置、投递和 Provider 失败
- 认证、授权、配额、账单和依赖可用性

## 交互规则

- 未检查失败是否为瞬时错误前，不要建议重试。
- 不得把不确定诊断转换成写操作。
- 提供针对性检查，不要只给出泛化的“继续分析”。
- 证据不足时，询问缺失范围，或用 `send_message` 让用户在具体资源中选择。
- 工具失败时，如有稳定错误码和请求或 Trace 标识，应保留它们。
- 展示日志或第三方消息时进行安全摘要，避免暴露密钥。
