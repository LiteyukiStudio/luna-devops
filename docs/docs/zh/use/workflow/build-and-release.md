# 构建与发布

## 从源码构建

构建会读取绑定的代码仓库，根据 Dockerfile 生成镜像并推送到镜像站。开始前确认：

- Git 凭据可以读取仓库和目标分支。
- 镜像站凭据包含推送权限。
- 构建参数中没有明文 Secret；敏感值使用密钥变量。

若镜像站显式引用的推送凭据或构建关联的部署目标已经不存在、当前用户无权使用或查询失败，构建会直接失败，不会自动改用其他凭据或默认目标。修复引用后再重新构建。

启动构建后查看日志，直到任务进入成功或失败终态。建议为生产镜像使用唯一、可追溯的 Tag。

## 发布

发布会把选定镜像部署到运行集群。创建 Release 后检查：

1. Release 已进入成功终态。
2. 工作负载的就绪副本达到期望副本，例如 `2/2`。
3. 容器日志和健康检查正常。
4. Service 在集群内可以访问。

> “发布成功”只表示发布流程完成，不保证应用当前仍然健康。运行状态以集群实时观察为准；集群不可达时平台会显示“不可用”，不会用旧状态代替。

需要自动交付时，再开启构建成功后自动发布或仓库 Webhook。首次上线建议保留手动步骤，确认每一段都正常后再自动化。
