# 数据保留与清理

平台管理员可以在“站点设置 → 数据保留”中设置自动保留时间，也可以预览并清理指定时间段的数据。

## 自动保留

| 数据 | 默认保留时间 | 清理范围 |
| --- | ---: | --- |
| 平台事件 | 90 天 | 过期事件 |
| 通知投递 | 90 天 | 已结束的投递 |
| Worker 任务事件 | 30 天 | 历史任务轨迹 |
| 构建日志 | 30 天 | 已结束构建的日志，不删除构建记录 |
| 发布日志 | 90 天 | 已结束发布的日志，不删除发布记录 |
| Hook 日志 | 90 天 | 已结束 Hook 的日志，不删除运行结果 |
| 过期认证数据 | 30 天 | 已过期的会话和验证数据 |

设置为 `0` 会停用对应数据的自动清理。修改设置只影响之后的清理任务，不会立即删除数据。正在运行的任务日志和仍然有效的会话不会被清理。

## 手动清理

手动清理仅限平台管理员使用。启用二次验证策略后，执行前还需要完成 MFA 验证。

1. 选择数据类型和时间范围。
2. 执行预览，确认每类数据的匹配数量。
3. 核对范围后，在确认对话框中执行清理。

预览不会修改数据。修改条件后必须重新预览。清理不可撤销，执行结果会写入审计日志；请在确认前导出需要长期保留的数据。

## 不会被清理的数据

审计日志、账单与用量账本、构建和发布记录、Hook 运行结果、Secret 与身份配置，以及 Kubernetes PVC 和应用运行数据不在此功能的清理范围内。

日志清理后，相关构建和发布记录仍会保留，但日志正文无法再查看。需要长期留存时，请提前接入外部日志系统或归档存储。
