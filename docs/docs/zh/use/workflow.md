# 平台功能怎么配合

Luna DevOps 把代码、镜像、集群和访问入口连接成一条交付路径：

```text
项目空间 → 应用 → 部署配置 → 构建 → 发布 → 访问入口
```

第一次部署可以参考[部署上线一个 Web 项目](/start/first-project)。

## 1. 项目空间

项目空间是团队、权限和资源的边界。成员、应用、构建、发布和访问入口都归属于项目空间。通常可以按产品、团队或客户划分。

添加成员时应从平台用户中选择，并按实际职责授予最小权限。

## 2. 应用

应用代表一个可独立部署的服务。一个仓库可以拆成多个应用，例如 API、Web 和 Worker。

应用拓扑可以查看当前工作负载及其依赖关系。项目空间还可以记录应用之间的关系；服务引用可能改变源服务下一次发布时的配置。删除被其他服务引用的应用前，必须先处理引用关系。

## 3. 部署配置

部署配置决定应用从哪里构建、如何运行以及发布到哪个集群。首次创建时重点确认：

- 来源：代码仓库或已有镜像。
- 环境阶段和目标运行集群。
- 镜像站与镜像地址。
- 服务端口、CPU、内存和副本数。
- 环境变量、Secret、配置文件和数据卷。
- 构建成功后是否自动发布。

建议先用已有镜像验证运行和访问链路，再接入 Git Provider 与自动构建。

## 4. 构建与发布

构建把代码生成镜像，发布把选定镜像部署到运行集群。发布后应检查 Release、工作负载、日志和健康状态，不能只以任务“已提交”作为完成依据。

配置或镜像变化后需要创建新 Release。使用不变的镜像 Tag 会增加版本判断和回滚难度，生产环境建议使用可追溯的唯一 Tag。

## 高级运行配置

大多数服务可以保留默认值。只有应用确有需要时，再配置健康检查、启动命令、StatefulSet、自动伸缩、调度规则、安全上下文、辅助容器和高级存储选项。

PVC 的存储类型通常只能在创建时确定，后续不要依赖平台自动迁移。`emptyDir` 数据会随 Pod 销毁，也不包含在数据导出中。修改存储或保留数据前，请确认备份和恢复方案。

删除应用时，平台默认保留其托管 PVC，并将它们登记为可重新认领的数据卷。需要恢复旧数据时，可在同一运行集群的新部署配置中选择对应保留卷。只有明确选择“永久删除数据卷”并完成确认后，平台才会删除 PVC；操作前建议先导出备份。

公共配置可以选择跟随最新值或保存快照。部署钩子适合数据库迁移等一次性步骤；失败的钩子可能阻止发布继续，请确保脚本可重复执行并准备回滚方式。

## Web Console 与数据导出

Web Console 是否可用受项目设置、账号权限和 MFA 策略限制。终端操作会被审计，不应在终端中输出或粘贴不必要的密钥。

数据导出仅适用于平台托管或已绑定的 PVC，并需要项目 Owner/Admin 权限和必要的二次验证。导出不包含 `emptyDir`。导出或清理数据前，请确认文件大小、敏感信息和存储位置。

## 访问入口

访问入口把域名、路径和 TLS 连接到应用服务。创建后应检查下发状态、域名解析、Service 端口和应用健康状态。

### TLS 选择

| 场景 | 推荐模式 |
| --- | --- |
| CDN 或外层代理已经处理 HTTPS | 上游代理已终止 TLS |
| 集群 Gateway 使用已有证书 | Gateway 终止 TLS |
| 使用 cert-manager HTTP-01 | HTTP Challenge 证书 |
| 使用 DNS-01 通配符证书 | 在集群中配置通配符证书 |

平台只使用运行集群中已经配置的 Gateway、Issuer 和证书资源，不会自动创建 ACME 账号或 DNS Provider 凭据。

如果 OIDC 等应用生成了错误的 `http` 回调地址，应检查 CDN、反向代理和 Gateway 是否正确传递外部协议。修改转发头或 TLS 链路可能影响所有入口，请由平台管理员评估后操作。
